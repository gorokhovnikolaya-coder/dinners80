# Задача из плана ТЗ

Аргумент — номер задачи: $ARGUMENTS. Если номера нет — возьми первую невыполненную задачу из раздела «План задач для агентов» и уточни у пользователя, её ли делать.

## 1. Подготовка

- `git status`: рабочее дерево должно быть чистым. Если нет — остановись и спроси.
- Убедись, что задачи, от которых зависит эта, отмечены в ТЗ как выполненные (номер меньше и в той же или предыдущей фазе). Если нет — предупреди пользователя.
- Создай ветку от `main`: `git switch main && git switch -c task/NN-<slug>` (NN — двузначный номер, slug — 2–3 английских слова).

## 2. Требования

- Прочитай текст задачи в ТЗ и все связанные разделы: экран, модель данных, API, интеграцию с Telegram, нефункциональные требования, «Принятые решения».
- Прочитай `docs/progress.md` (заметки прошлых задач) и `docs/decisions/`.
- Если что-то в требованиях неясно или противоречит — задай вопрос пользователю до кода. Мелкие технические решения принимай сам и записывай в `docs/decisions/`.
- Сверь с актуальной документацией все внешние API, которые задача использует (Telegram, Supabase, библиотеки).

## 3. Реализация

- Сначала чистая логика и её юнит-тесты (`packages/shared`), потом API/моки, потом UI.
- Держись границ задачи; находки вне её — в «Заметки» `docs/progress.md`.

## 4. Проверка

1. `pnpm check` — зелёный.
2. Если менялся UI: `pnpm e2e` — зелёный; добавь Playwright-сценарий основного действия экрана; запусти субагента `ui-verifier` с номером задачи и списком состояний; исправь найденное.
3. Запусти субагента `spec-reviewer` с номером задачи; исправь найденное или явно объясни пользователю, почему не исправляешь.

## 5. Завершение

- Отметь чекбокс задачи в ТЗ (`- [ ]` → `- [x]`).
- Добавь запись в начало раздела «Журнал» `docs/progress.md` по шаблону из файла.
- Закоммить: `git add -A && git commit` с сообщением `task NN: <summary>`.
- Не мёржи в `main` и не пушь.

## 6. Отчёт пользователю

Коротко: что сделано, как проверено (команды и результат), скриншоты (пути), принятые решения, что осталось или вызывает сомнения, имя ветки для приёмки.
