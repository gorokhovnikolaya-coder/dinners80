# 0001. Стек: Redux Toolkit, Node.js-сервер, nginx на VPS вместо Supabase

Дата: 2026-10-09 · Задача: — (до задачи 1)

## Контекст

В исходном ТЗ клиент использовал Zustand и TanStack Query, бэкенд целиком жил в Supabase (Postgres + RLS, Storage, Edge Functions на Deno, cron), а перед ним стоял прокси (Cloudflare Worker или nginx — открытый вопрос). Владелец продукта решил сменить стек.

## Решение

- **Клиент:** Redux Toolkit для клиентского состояния и RTK Query для запросов и кеша вместо Zustand и TanStack Query. MSW для моков остаётся.
- **Бэкенд:** свой сервер на Node.js 24 + TypeScript, полностью без Supabase.
  - HTTP — Fastify; контракт — те же zod-схемы из `packages/shared`.
  - База — Postgres 17, доступ через Drizzle ORM, миграции — SQL-файлы в `apps/server/migrations/`.
  - Бот — grammY в том же сервере, режим вебхука с проверкой `X-Telegram-Bot-Api-Secret-Token`.
  - Расписание (напоминания, очистка `share`) — отдельный процесс-воркер из того же кода.
  - Файлы — на диске VPS: приватная папка `cooks`, публичная `share`.
- **Инфраструктура:** один VPS. nginx отвечает за TLS и раздачу статики мини-аппа, проксирует `/api/*` на Node и раздаёт `/media/share/*` публично, а `/media/cooks/*` — только по подписанной сервером ссылке на 1 час (модуль `secure_link`). Всё запускается через Docker Compose. Локально Postgres тоже работает в Docker Compose.
- **Загрузка фото:** клиент отправляет файл в `POST /api/uploads/*` (multipart), а не по подписанной ссылке в Storage.
- **Права:** RLS больше не нужен, потому что клиент не подключается к базе. Сервер работает под ролью без прав суперпользователя, порт Postgres наружу не открыт.

## Альтернативы

- **Только Zustand → RTK, запросы на TanStack Query.** Отказались в пользу одного стека для состояния и запросов.
- **Node-сервер поверх Supabase (Postgres и Storage в облаке).** Отказались: остаётся зависимость от `*.supabase.co`, нестабильного из России, и нужен прокси.
- **Express / Hono вместо Fastify.** Выбран Fastify: встроенная валидация схем, хорошая типизация и плагины для multipart и rate limit.
- **Prisma / Kysely вместо Drizzle.** Выбран Drizzle: лёгкий, без отдельного движка, миграции — обычные SQL-файлы.
- **S3 / MinIO вместо диска.** На одном VPS диск проще; к S3 можно перейти, не меняя API.

## Последствия

- В ТЗ обновлены модель данных (без RLS), API (префикс `/api`, загрузки через multipart), интеграция с Telegram, стек, структура репозитория, задачи 1, 14, 15, 17, 21, 23 и раздел «Принятые решения»; из открытых вопросов убран выбор между Cloudflare и nginx.
- На проекте появляются эксплуатационные обязанности: обновления VPS, TLS-сертификаты, ежедневные бэкапы базы и файлов вне VPS (в задаче 23).
- RTK Query вместе с react-redux тяжелее TanStack Query и Zustand примерно на 30–40 КБ gzip, но в лимит 200 КБ стартового бандла укладываемся.
- Edge Functions на Deno больше нет, поэтому `packages/shared` импортируется сервером как обычный workspace-пакет.
- Хук `guard-edit.sh` охраняет миграции в `apps/server/migrations/`.

## Дополнение: npm вместо pnpm

Менеджер пакетов — npm (workspaces) из поставки Node 24 вместо pnpm через corepack. Lock-файл — `package-lock.json`. Команды вызываются как `npm run <скрипт>`, для отдельного пакета — `npm run <скрипт> -w <пакет>`. Хук `stop-check.sh` запускает `npm run -s typecheck` и `npm run -s lint`.
