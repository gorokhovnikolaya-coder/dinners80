# 0017. Авторизация: проверка initData и `POST /auth`

Дата: 2026-10-16 · Задача: 15

## Контекст

ТЗ задаёт алгоритм подписи initData, окно в 24 часа и правила приглашений («Интеграция с Telegram»). Оно не определяет:
- как проверка подключается к эндпоинтам;
- формат `invite_code`;
- что обновлять у существующего пользователя;
- как быть с расхождением часов;
- что отвечать пользователю, которого нет в базе.

Продуктовые вопросы (`invite_joined`, неизвестный пользователь) согласованы с пользователем 2026-10-16.

## Решение

- **Подпись** — по core.telegram.org («Validating data received via the Mini App»):
  - data-check-string — все полученные поля, кроме `hash` (`signature` входит), отсортированные по ключу, в виде `key=value` через `\n`;
  - секрет — `HMAC_SHA256(key = "WebAppData", data = BOT_TOKEN)`;
  - hex от `HMAC_SHA256(key = секрет, data = data-check-string)` сравнивается с `hash` через `timingSafeEqual`.

  Повторяющийся ключ, `hash` не из 64 hex-символов и `auth_date` не числом — отказ. Код: `apps/server/src/auth/initData.ts` (`validateInitData`, `validateAuthorization`, `signInitData` — подпись для тестов и, в задаче 16, для локального режима).
- **Срок** — `auth_date` старше 24 часов отклоняется. Данные «из будущего» допускаются с запасом до 5 минут на расхождение часов, дальше — отказ.
- **`user`** обязателен: id > 0, `first_name`. Без него — отказ. Сервер берёт только `id`, `first_name`, `username`, `photo_url`, `allows_write_to_pm`; остальное не хранит.
- **`start_param`** принимается, только если он похож на значение `startapp` (`[A-Za-z0-9_-]{1,64}`), иначе игнорируется.
- **Подключение — deny by default.** Один хук `onRequest` на всё приложение (`auth/plugin.ts`, регистрируется до маршрутов). Режим маршрута задаётся опцией `config.auth`:
  - `user` (по умолчанию) — верная подпись и пользователь есть в базе, иначе `401 unauthorized`; пользователь лежит в `request.user`;
  - `initData` — только подпись (`POST /auth`);
  - `public` — без заголовка (`/api/health`, в задаче 18 — вебхук бота со своим секретом).

  Хук работает в `onRequest`, до разбора тела. Обработчики берут данные через `requireUser` / `requireInitData`.
- **Ошибки** — единый формат `{error: {code, message}}` (`http/errors.ts`):
  - `ApiHttpError` → свой статус и код;
  - клиентские ошибки Fastify (битый JSON, размер тела) → `validation` с их статусом;
  - неизвестный маршрут → `404 not_found`;
  - остальное → `500 internal` и запись в лог.
- **`POST /auth`** — одна транзакция (`db/users.ts`, `signIn`):
  1. Upsert по `tg_id`; новизну строки показывает `xmax = 0` в `returning`.
  2. На каждом входе обновляются `first_name`, `username`, `photo_url` (как в initData, отсутствующие — `null`) и `last_seen_at`.
  3. `bot_can_write` из initData только поднимается (`old or allows_write_to_pm`) и никогда не сбрасывается. `reminder_enabled` не меняется.
  4. Приглашение: если код в `start_param` чужой и известный — дружба в обе стороны (`on conflict do nothing`). Для нового пользователя ещё `invited_by` и событие `invite_joined` с `{inviter_id}`. Неизвестный или собственный код молча игнорируется, вход проходит.

  Ответ — `authResponseSchema`, как в моке:
  - `needsOnboarding` = `onboarded_at is null`;
  - подписка — по последней по `expires_at` записи без `refunded`; `active`, если её статус `active` и срок в будущем.
- **`invite_code`** — 10 случайных символов `[A-Za-z0-9]` (`crypto.randomInt`, ≈ 59 бит). При редком совпадении с чужим кодом транзакция повторяется (до 3 попыток).
- **Окружение** — токен в `BOT_TOKEN`. Сервер без него не стартует (`config.ts`). В `.env.example` значение пустое: подставной токен там был бы опасен, если файл скопируют на прод. `buildApp({ db, botToken, now? })` получает зависимости явно.

## Альтернативы

- `preHandler` на каждом маршруте или вызов `authenticate()` в обработчике — новый эндпоинт легко оставить без проверки.
- `fastify-plugin` и отдельный плагин с декораторами — лишняя зависимость ради одного хука.
- Автосоздание пользователя на любом эндпоинте — отклонено: приглашение и создание должны жить в одном месте (`POST /auth`), клиент всегда вызывает его первым.
- Готовая библиотека `@tma.js/init-data-node` — алгоритм занимает 20 строк на `node:crypto`, а лишняя зависимость на сервере не нужна.

## Последствия

- Задача 16:
  - новые эндпоинты по умолчанию требуют пользователя и берут его через `requireUser(request)`;
  - для `VITE_API=local` клиенту нужна initData, подписанная тестовым токеном (`signInitData`; токен не должен попасть в продакшен-сборку).
- Задача 18: вебхук объявляется с `config: { auth: 'public' }` и проверяет `X-Telegram-Bot-Api-Secret-Token`. Создание дружбы для `/start <код>` можно вынести из `applyInvite` в общую функцию.
- Задача 22: событие `invite_joined` уже пишется сервером; остальные события — там.
