# 0023. Воркер: напоминания об ужине и очистка `share`

Дата: 2026-10-17 · Задача: 21

## Контекст

ТЗ задаёт напоминание («одно сообщение в день в `reminder_time` по часовому поясу пользователя, только при `reminder_enabled` и `bot_can_write`; блюдо дня — первая карточка выдачи «Будни» — и кнопка открытия мини-аппа», сброс `bot_can_write` при 403, соблюдение лимитов Bot API) и удаление картинок `share` старше 30 дней отдельным процессом-воркером. Не определены: текст сообщения, поведение при пропущенном времени, пользователи без онбординга, защита от повторной отправки, расписание и запуск воркера.

## Решение

Продуктовые ответы пользователя (2026-10-17):

- Сообщение — фото блюда дня с подписью «Идея ужина на сегодня — {Блюдо} ({Страна}), {N} мин. Рецепт по шагам — в приложении.» и кнопкой «Открыть» (web_app на `WEBAPP_URL` — главный экран). Если Telegram не принял фото (`400`, например фото контента ещё не опубликовано) — тот же текст без фото.
- Пользователю без пройденного онбординга (`onboarded_at` пуст, напоминания включены `/start`) — «Пора выбрать ужин! Ответьте на три коротких вопроса — подберём блюдо под вас.» и «Открыть».
- Напоминание шлётся и тогда, когда пользователь сегодня уже готовил.
- Пропущенное (воркер был остановлен) досылается, если от `reminder_time` прошло не больше 2 часов и у пользователя тот же календарный день; иначе день пропускается.

Технические решения:

- Воркер — отдельный процесс того же кода: `apps/server/src/worker/index.ts`, запуск `npm run worker -w @tma80/server` (прод), `npm run dev:worker` (локально, `.env`). Нужны `DATABASE_URL`, `BOT_TOKEN`; `MEDIA_DIR`/`MEDIA_URL` — как у сервера; без `WEBAPP_URL` напоминания выключены (нечем открыть мини-апп), очистка работает. Docker Compose для VPS в репозитории пока нет — сервис воркера добавится вместе с ним.
- Напоминания проверяются раз в минуту (в начале минуты), задачи не перекрываются; ошибка пишется в лог, расписание продолжается. Логи — JSON-строки в stdout/stderr.
- «Сегодня уже отправлено» — новое поле `users.reminder_sent_on date` (миграция `0004`): локальная дата последнего напоминания. Перед отправкой день «забирается» условным `UPDATE … WHERE reminder_sent_on IS DISTINCT FROM <день>` — два воркера или тика не пришлют второе сообщение. Отметка снимается (следующий тик повторит отправку, пока окно 2 часа не закрылось), только когда сообщение точно не ушло: `429` после исчерпания повторов, `5xx` Telegram или ошибка до вызова Bot API (например, базы). Прочие `4xx` (например, `400 chat not found`) отметку оставляют — иначе повтор каждую минуту; сетевая ошибка (`HttpError`) тоже оставляет — Telegram мог уже принять сообщение, лучше пропустить день, чем прислать дубль. Всё это пишется в лог с `retry`.
- Расчёт «пора ли» — чистая функция `dueReminderDate` в `packages/shared/src/reminders.ts` (юнит-тесты): локальные дата и минуты через `Intl` в `users.timezone`; неизвестный пояс — пропуск.
- Блюдо дня — `suggestDishes` в режиме `weekday`, страница 0, с теми же входными данными, что `GET /home` (готовки, подписка, исключения; порядок дня зависит от даты и id пользователя) — то же, что первым увидит пользователь на главном в будни. Если первая карточка закрыта замком или блюд нет — текст «Пора выбрать ужин! Откройте приложение — подберём блюдо на сегодня.» без фото. Адрес фото — `MEDIA_URL/content/…`, абсолютный по origin `WEBAPP_URL`.
- Ответ `403` — `bot_can_write = false` (бот заблокирован или пользователь удалён); `429` — ожидание `retry_after` и до 3 повторов; между сообщениями пауза 40 мс (≤ 25 в секунду при лимите Bot API ~30).
- Очистка `share`: при старте и раз в сутки удаляются `share/{uuid}.jpg` с временем изменения старше 30 дней (`SHARE_CARD_TTL_DAYS`), их имена обнуляются в `cooks.share_card`. Повторное «Поделиться» такой готовки загружает новую карточку (загрузка уже умела заменять пропавший файл, решение 0022). Осиротевшие фото `cooks/` не трогаем (решение пользователя от 2026-10-17).

## Альтернативы

- Отбор «пора ли» в SQL (`now() AT TIME ZONE timezone`) — одна некорректная зона роняет весь запрос; для закрытого теста выборка всех включённых пользователей раз в минуту дешёвая. При росте — добавить фильтр в SQL.
- Очередь задач (pg-boss, BullMQ) и cron-библиотеки — лишняя зависимость для двух периодических задач.
- Плагин `@grammyjs/auto-retry` — нужен только простой повтор на 429, реализован на месте.

## Последствия

- В деплой (Docker Compose на VPS) нужен второй процесс из того же образа: `npm run worker -w @tma80/server` с тем же окружением, что у сервера, и тем же `MEDIA_DIR`.
- Событие `app_open` с источником «напоминание» (задача 22) потребует метки в адресе кнопки — сейчас кнопка открывает `WEBAPP_URL` без параметров.
