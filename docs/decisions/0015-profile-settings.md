# 0015. Профиль: автосохранение, напоминание с `requestWriteAccess`, статусы подписки, документы

Дата: 2026-10-16 · Задача: 13

## Контекст

ТЗ (экран 9) перечисляет содержимое профиля: аватар, имя и счётчики; ответы онбординга теми же контролами; напоминание с `requestWriteAccess`; подписку; ссылки на документы. Макета профиля нет. ТЗ не определяет:

- как сохранять изменения;
- порядок блоков и тексты;
- что показывать, когда напоминание включено, а бот писать не может;
- запасной вариант для клиента без `requestWriteAccess`;
- тексты статусов подписки;
- где живут документы, тексты которых — открытый вопрос.

Владелец продукта 2026-10-16 принял рекомендации исполнителя по всем пунктам. Продуктовые правила внесены в ТЗ: экран 9, «Принятые решения», «Открытые вопросы».

## Решение

**Продуктовые правила (одобрены владельцем):**

- Автосохранение: каждое изменение сразу уходит в `PATCH /me`. При ошибке значение откатывается, внизу появляются «Не удалось сохранить. Проверьте интернет и попробуйте ещё раз.» и «Повторить».
- Порядок блоков: шапка → напоминание → подписка → ответы онбординга → документы.
  - «Изменить исключения» на главном открывает `/profile#exclusions`: экран прокручивается к «Что не едите», фокус встаёт на заголовок.
- Переключатель напоминания показывает фактическое состояние: он включён, только если `reminderEnabled` и бот может писать.
  - При включении без разрешения вызывается `requestWriteAccess`. При отказе переключатель остаётся выключенным, без сообщения.
  - В клиенте без метода переключатель неактивен, под ним «Обновите Telegram, чтобы включить напоминания».
- Подписка:
  - действует — «Подписка активна до 5 ноября», без кнопки;
  - не было (или период не закончился, но подписка не действует — возврат) — «Бесплатно — 10 стран на выбор»;
  - закончилась — «Подписка закончилась 5 ноября»;
  - в обоих последних случаях кнопка «Открыть все страны» ведёт на `/paywall`.
- Документы — внешние страницы из переменных сборки `VITE_TERMS_URL` и `VITE_PRIVACY_URL`, только https.
  - Открываются через `openLink` с `tryInstantView`, вне Telegram — в новой вкладке.
  - В `npm run dev` без переменных подставляются заглушки `https://example.com/tma80/…`. В продакшен-сборке ссылка без адреса скрыта, а без обеих скрыт весь блок.
- Время напоминания — нативный `select` на 48 значений, 00:00–23:30 (`REMINDER_TIMES` в `packages/shared`). При выключенном напоминании поле скрыто. Под именем — @username. Счётчики берутся из `GET /map` и не нажимаются.

**Технические решения:**

- Автосохранение — `createAutosave` (`screens/profile/autosave.ts`), чистая очередь без React:
  - одновременно в полёте только один `PATCH /me`. Изменения, сделанные за это время, сливаются (новые поля побеждают) и уходят следующим запросом — ответы не приходят не по порядку, старый ответ не перетирает новое значение;
  - экран показывает профиль из кеша `POST /auth` с наложенными несохранёнными изменениями (`applyProfilePatch` из `packages/shared`, им же пользуется мок-бэкенд). Значения меняются мгновенно, при ошибке изменение уходит из наложения — это и есть откат;
  - упавшие поля хранятся в `failed` до «Повторить». Новое изменение того же поля вытесняет упавшее;
  - экран подписан через `useSyncExternalStore`. Запрос отправляется через `meApi.endpoints.updateMe.initiate` — не через хук, чтобы изменения, сделанные перед уходом с экрана, всё равно сохранились, — и после ответа удаляется из стора (`reset`).
- Ответ `PATCH /me` обновляет кеш `auth`, как в онбординге. Изменённый ответ онбординга (`changesPreferences`) инвалидирует новый тег `Preferences`:
  - его выдают `GET /home` (время в будни и исключения меняют подборку);
  - и `GET /dishes/:id` без `servings` (порции по «кто ест»);
  - смена напоминания подборку не трогает.
- Свои исключения сохраняются так же: `ExclusionsField` без `commitPending` — слово добавляется «Добавить»/Enter и сразу уходит в `PATCH`. `exclusionsPatch` отправляет только изменившуюся часть, нормализованной.
- С изменением напоминания (включение, время) отправляется часовой пояс устройства, если он отличается от сохранённого (`withTimeZone`): напоминание приходит в `reminderTime` по поясу пользователя, а пользователь мог переехать после онбординга.
- Разрешение писать:
  - `telegram/writeAccess.ts`: `canRequestWriteAccess` (`requestWriteAccess.isAvailable()`, Mini Apps 6.9+) и `askWriteAccess` (true только для `allowed`, ошибка — как отказ);
  - сервер узнаёт о разрешении из вебхука бота (служебное сообщение `write_access_allowed` с `web_app_request`, задача 18), и это может случиться позже ответа на `PATCH /me`. Поэтому выданное в сессии разрешение клиент помнит в ленивом слайсе `profile` (`writeAccessAllowed`), а `reminderView` считает бота способным писать, если так говорит сервер или слайс;
  - сам флаг `botCanWrite` клиент серверу не отправляет: сервер клиенту не доверяет.
- `Switch` (`components/Switch.tsx`) — новый общий компонент, показан в `/dev/ui`:
  - нативный `input type="checkbox" role="switch"` лежит невидимым (60 × 44) поверх нарисованного трека внутри `label`, поэтому нажимается вся строка;
  - имя — только подпись (`aria-labelledby`), вторая строка — описание (`aria-describedby`);
  - `busy` (пока открыто окно Telegram) ставит `aria-busy` и игнорирует нажатия;
  - выключенный трек — `muted`: ≥ 3:1 к белому, состояние видно и по положению ручки.
- `IconExternal` — у ссылок на документы. `openExternalLink` (`telegram/links.ts`) — `openLink.ifAvailable(url, { tryInstantView: true })`. Если Telegram не открыл ссылку, срабатывает обычная ссылка `<a target="_blank">`.
- Мок:
  - Telegram-мок отвечает на `web_app_request_write_access` через 300 мс статусом из `?mock_write_access=allowed|cancelled` (по умолчанию `allowed`);
  - при `allowed` он до ответа шлёт `window`-событие `tma80:mock-write-access`, и мок-бэкенд ставит `botCanWrite` (`allowWriteAccess`, хранится во вкладке), как вебхук;
  - `?mock_tg_version=6.0` даёт клиент без метода;
  - у пользователя 1003 месячная подписка закончилась 10 дней назад (`active: false`) — так видно состояние «Подписка закончилась»; доступ к странам по-прежнему как у бесплатного.

## Альтернативы

- **Кнопка «Сохранить».** Напоминание всё равно пришлось бы сохранять сразу из-за окна Telegram — на одном экране было бы две модели. Владелец выбрал автосохранение.
- **Оптимистичные правки прямо в кеше `auth` и параллельные запросы.** Ответы могут прийти не по порядку, а откат одного запроса затёр бы другой. Очередь с наложением проще проверить.
- **Отправлять `botCanWrite: true` в `PATCH /me` после `allowed`.** Сервер не должен верить клиенту в том, что знает сам из вебхука.
- **Показывать включённым напоминание, которое не придёт, с предупреждением.** Владелец выбрал фактическое состояние.
- **Страницы документов внутри мини-аппа.** Нужны тексты (открытый вопрос), и ради двух страниц пришлось бы тащить разметку текста в бандл. Внешние страницы меняются без сборки.
- **`input type="time"` со `step=1800`.** iOS не соблюдает шаг: можно выбрать 18:15, и сервер ответил бы 400.

## Последствия

- Задача 16: `PATCH /me` применяет поля как `applyProfilePatch` и нормализует исключения. `GET /home` и `GET /dishes/:id` зависят от профиля — клиент перезапрашивает их сам.
- Задача 18: бот на `write_access_allowed` (и на `/start`, `allows_write_to_pm`) ставит `bot_can_write = true`. Клиент до этого помнит разрешение сам.
- Задача 21: воркер шлёт напоминание при `reminder_enabled AND bot_can_write`, в `reminder_time` по `timezone`.
- Задача 22: событие `reminder_toggled` (enabled, time) — в `toggleReminder` и при смене времени профиля.
- Задача 23: перед закрытым тестом задать `VITE_TERMS_URL` и `VITE_PRIVACY_URL`, когда появятся тексты.
