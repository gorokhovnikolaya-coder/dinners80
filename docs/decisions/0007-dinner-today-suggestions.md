# 0007. «Ужин сегодня»: правила подбора, страницы, метки и карточка с замком

Дата: 2026-10-10 · Задача: 05

## Контекст

ТЗ (экран 1) задаёт порядок подбора и ослабление ограничений, но не определяет: режим при открытии, смысл метки «N-е блюдо», когда именно ослаблять правила и насколько, что делать с неполной последней страницей, повтор страны на странице, пустое состояние, вид карточки с замком, уровень на маленьких карточках, чип «2 порции» и место аватара (в макете его нет). Владелец продукта 2026-10-10 принял рекомендации исполнителя по всем пунктам; правила внесены в ТЗ (экран 1 и «Принятые решения»).

## Решение

**Продуктовые правила (одобрены владельцем):**

- Режим при открытии — по дню недели в часовом поясе пользователя: пн–пт «Будни», сб–вс «Выходные». Выбор переключателя держится, пока приложение открыто (Redux-слайс `home`, вместе с текущей страницей каждого режима).
- Знаменатель счётчика — число опубликованных стран из API (`countriesTotal`; в моке 12, на проде 30).
- Метки: `newCountry` — страна не пройдена; `nthDish` — N = число разных уже приготовленных блюд этой страны + 1; `cookedBefore` («Уже готовили») — это блюдо пользователь уже готовил.
- Порядок без ослабления: блюда непройденных стран → непробованные блюда пройденных стран → повторы старше 14 дней; внутри группы — случайный порядок дня.
- Ослабление — только если блюд меньше, чем мест на странице, и только до заполнения страницы, по одному блюду: сначала приготовленные за 14 дней (самая давняя готовка первой), затем в «Будни» блюда дольше выбранного времени (ближайшие по времени первыми).
- Страницы по 3; неполная последняя страница добирается с начала списка по кругу; при 3 и меньше блюдах кнопка «Показать другие» скрыта. На странице по возможности нет двух блюд одной страны: берётся первое по порядку блюдо страны, которой ещё нет на странице; блюдо поднимается выше своей группы только ради этого.
- Пустое состояние: «Под ваши ограничения блюд не нашлось» + «Изменить исключения» → профиль.
- Бесплатный пользователь с ≥ 10 пройденными странами без подписки (в том числе после её окончания): на странице 2 открытых блюда пройденных стран и последней — блюдо новой страны с замком (затемнённое фото, страна, название, замок, «Откроется с подпиской»; тап → пейвол `?dish=<id>`). Карточка с замком подчиняется режиму (сначала блюда в пределах времени, затем ближайшие по времени) и листается вместе со страницами. Если подходящего блюда новой страны нет — 3 открытые карточки.
- Большая карточка: фото, метка поверх фото, страна, название, чипы «время» и «уровень», без чипа порций. Маленькие: фото, «СТРАНА · МЕТКА», название, «25 мин · Вызов».
- Аватар 44 px слева от плитки стран: фото Telegram или первая буква имени; тап → профиль.

**Технические решения:**

- Алгоритм — `suggestDishes` в `packages/shared/src/suggestions.ts`, чистая функция: блюда (с названиями ингредиентов), готовки пользователя, профиль (исключения, время, часовой пояс, подписка), режим, страница, `now`. Возвращает `{page, pageCount, suggestions: {dishId, label, locked}[]}`. Сервер (задача 16) и мок вызывают её одинаково.
- Случайный порядок дня: ранг блюда = хэш (FNV-1a + финализатор murmur3) строки `<дата пользователя>:<user_id>|<dish_id>`; не зависит от порядка входа и одинаков весь день. Дата — `localDateKey(now, timezone)` через `Intl`.
- «Приготовлено за 14 дней» — последняя готовка блюда позже `now − 14 × 24 ч`.
- `GET /home?mode=&page=` → `homeResponseSchema`: `mode`, `page` (сервер берёт по модулю), `pageCount`, `suggestions` (карточка: `dishId`, `title`, `countryId`, `countryName`, `level`, `minutes`, `imageUrl`, `label`, `locked`), `countriesCount`, `countriesTotal`, `dishesCount` (число готовок, как в `POST /cooks`). Для блюда с замком отдаётся только превью — как в `403 paywall`. Сервер отдаёт готовый `imageUrl`, клиент не собирает пути к медиа.
- «Показать другие» запрашивает `(page + 1) % pageCount`; пока грузится следующая страница, старые карточки остаются, кнопка в состоянии загрузки. При смене режима — скелетон карточек.
- В моке фото блюд — SVG-градиенты `data:` (`mocks/fixtures/images.ts`); `?mock_error=home` — ошибка `GET /home`.
- Маршруты будущих экранов объявлены в `ROUTES` (`/dishes/:id`, `/map`, `/friends`, `/paywall`, `/profile`); пока экранов нет, роутер отправляет на главный. `TabBar` подключён к `navigate` (`MainTabBar`).
- Имя пользователя на главном больше не выводится текстом: e2e узнают пользователя по ссылке аватара «Профиль: <имя>».

## Альтернативы

- **Ослаблять целым уровнем** (все недавние, затем все длинные) — больше страниц, но в «Будни» быстро всплывают блюда дольше выбранного времени; владелец выбрал «только до 3».
- **Неполная последняя страница** — 1–2 карточки ломают макет «большая + 2 маленькие».
- **Seed через ГПСЧ и перемешивание** — порядок зависел бы от порядка блюд во входе (и в выдаче базы); ранг по хэшу стабилен.
- **Считать подбор на клиенте** — клиент не должен знать запреты доступа и чужие данные; подбор на сервере, клиенту — готовая страница.
