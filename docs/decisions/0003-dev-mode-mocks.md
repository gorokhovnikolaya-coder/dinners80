# 0003. Dev-режим: SDK `@tma.js/sdk-react`, тестовые пользователи, фикстуры и MSW

Дата: 2026-10-09 · Задача: 02

> **Обновлено решением [0006](0006-light-onboarding-custom-exclusions.md) (2026-10-10):** тега `pork` больше нет — блюда со свининой помечены только `meat`; пользователи 1002 и 1004 вместо «без свинины» исключают своё слово «свинина» (`customExclusions`).

## Контекст

ТЗ требует, чтобы мини-апп запускался в обычном браузере: `VITE_TG_MOCK=1` (подставное окружение Telegram, пользователи переключаются через `?user=`) и `VITE_API=mock` (MSW по фикстурам: 12 стран, 36 блюд, 3 друга, состояния «новичок», «8 стран», «10 стран без подписки», «10 стран с подпиской», «бот не может писать»). ТЗ не определяет:

- какой пакет SDK брать, если указанный в ТЗ пакет переименован;
- id тестовых пользователей и формат фикстур;
- как подписывается mock initData;
- как не пустить MSW и моки в продакшен-сборку;
- регистр полей в JSON API.

## Решение

**SDK — `@tma.js/sdk-react` 3.x** (согласовано владельцем; ТЗ обновлено: строка стека «Мини-апп» и пункт «Совместимость» в НФТ, а также правило в AGENTS.md) (сейчас 3.0.23, ядро `@tma.js/sdk` 3.3). В ТЗ указан `@telegram-apps/sdk-react`, но проект Telegram Mini Apps переименовал пакеты в `@tma.js/*`. Документация на docs.telegram-mini-apps.com описывает уже `@tma.js/*` и даёт гайд по миграции с `@telegram-apps/*`. Последний `@telegram-apps/sdk-react` (3.3.9) выходил в декабре 2025 года, а `@tma.js/*` продолжают обновляться. API тот же по смыслу, отличаются имена: `miniApp.setBgColor` вместо `setBackgroundColor`, `.ifAvailable()` возвращает `{ ok, data }`. Проверка поддержки методов в старых клиентах делается через `fn.isAvailable()` / `fn.ifAvailable()` / `fn.supports('rgb')`: они сверяют версию Mini Apps клиента. Это и есть замена `isVersionAtLeast` из ТЗ.

**Запуск Telegram (`src/telegram/sdk.ts`):** `init()`, `miniApp.mount`, `setHeaderColor` (hex, если клиент поддерживает `rgb`, иначе `bg_color`) и `setBgColor` цветом фона из макета `#F3F5F7` (в задаче 3 его заменит токен), `ready()`, `viewport.mount()` + `bindCssVars()` (CSS-переменные `--tg-viewport-safe-area-inset-*` и `--tg-viewport-content-safe-area-inset-*`), `expand()`. Каждый вызов проверяется на доступность. Вне Telegram `init()` падает. Ошибка логируется, а приложение всё равно рендерится и показывает состояние ошибки, потому что без initData `POST /auth` вернёт 401.

**Mock-окружение (`src/telegram/mock/`):** `mockTelegramEnv` с launch params (светлая тема Telegram, версия Mini Apps `9.0`, платформа `ios`) и `onEvent`, который отвечает на `web_app_request_theme`, `…_viewport`, `…_safe_area` (низ 34 px, как у iPhone 14 без полноэкранного режима), `…_content_safe_area` (нули). Имена всех вызванных методов складываются в `window.__tgMockCalls`, чтобы e2e могли проверить `ready`, `expand` и установку цветов.

**initData в mock-режиме:** строка формируется так же, как у Telegram (`user` в JSON, `auth_date`, `chat_type`, `chat_instance`, `signature`, `hash`), но `hash` и `signature` равны `mock`. MSW подпись не проверяет и берёт пользователя по `user.id`. Подпись тестовым токеном для `VITE_API=local` остаётся задачам 15–16: секрет нельзя класть в клиентскую сборку, поэтому, скорее всего, initData будет подписывать dev-эндпоинт локального сервера.

**Тестовые пользователи (`?user=<id>`, id — Telegram id в initData):**

| id | Имя | Состояние |
| --- | --- | --- |
| 1001 | Аня | новичок: нет готовок, `needsOnboarding: true`, ответы онбординга `null` |
| 1002 | Борис | 8 стран, без свинины, 3 друга (по умолчанию) |
| 1003 | Вера | 10 стран без подписки (нет Таиланда и Колумбии) |
| 1004 | Глеб | 10 стран (нет Индии и Таиланда), месячная подписка ещё на 20 дней, без свинины |
| 1005 | Дина | бот не может писать: `botCanWrite: false`, `allows_write_to_pm: false`, напоминания выключены, 3 страны |
| 2001–2003 | Егор, Жанна, Зоя | друзья: 5, 8 (без глютена) и 11 стран (у Зои годовая подписка) |

Если `?user` нет, берётся пользователь, выбранный раньше в этой вкладке (sessionStorage `tma80:mock-user`), иначе 1002. Так выбор переживает навигацию внутри приложения, которая теряет query-параметр. Если id неизвестен, в консоль пишется предупреждение и берётся 1002.

**Фикстуры (`src/mocks/fixtures/`)** — TypeScript-модули с типами из `packages/shared`, без JSON. Юнит-тест прогоняет каждую запись через zod-схему и проверяет инварианты: 12 стран на 3 континентах, по одному блюду каждого уровня на страну, состояния пользователей, готовки не нарушают запреты пользователя. Инварианты в тесте также требуют: блюдо с тегом `pork` всегда имеет и `meat`, а у пользователей 1003 и 1004 есть хотя бы одно блюдо непройденной страны, разрешённое их запретами. Id блюда — `<страна>-<slug>`.

**Теги блюд — решение владельца: свинина тоже мясо.** Каждое блюдо со свининой помечено и `pork`, и `meat`, поэтому запрет «мясо» исключает и свинину. Правило внесено в ТЗ (модель данных, `dishes.tags`). Глютен ставится последовательно: мука, паста, хлеб, тесто и соевый соус (оякодон, гунбао, ломо сальтадо, пад кра пао, мусака, оссобуко, говядина по-бургундски). Даты готовок задаются как «N дней назад» и считаются от текущего момента, чтобы правило 14 дней и рейтинг «Эта неделя» работали в любой день. Фото контента (`imagePath`) пока указывают на несуществующие файлы, их обработают экраны.

**Схемы в `packages/shared`:** `countrySchema`, `dishSchema` (без ингредиентов и шагов), `cookSchema`, `userProfileSchema`, `subscriptionStatusSchema` (`active`, `plan`, `expiresAt`), `authResponseSchema` (`user`, `subscription`, `needsOnboarding`), `apiErrorSchema` с кодами ошибок из ТЗ и константы (уровни, теги, household, время, тарифы, лимит 10 стран). **Поля JSON API — camelCase**, как в ответе `POST /cooks` из ТЗ (`cookId`, `newCountry`). Перевод из snake_case колонок базы делает сервер. Id сущностей в контракте — строки, а тип колонок выберет задача 14.

**Ошибки и задержки в mock-режиме.** `page.route` в Playwright не видит запросы, которые обслуживает service worker MSW, поэтому управление встроено в моки (`src/mocks/controls.ts`) и задаётся параметрами URL при загрузке страницы:

- `?mock_error=<ключ>[,<ключ>]` — первый запрос к эндпоинту падает с HTTP 500 `{error: {code: 'internal', message}}`, а повтор проходит, что удобно для сценария «Повторить»;
- `?mock_error=<ключ>:always` — эндпоинт падает всегда;
- `?mock_delay=<мс>` — задержка всех ответов, чтобы увидеть состояние загрузки.

Ключ эндпоинта — короткое имя (`auth`); новые обработчики вызывают `takeFailure(controls, '<ключ>')`. Для ответа 500 в `API_ERROR_CODES` добавлен код `internal`, потому что в ТЗ перечислены только коды бизнес-ошибок, а у непредвиденной ошибки сервера тоже должен быть код в едином формате.

**MSW 2.x** (2.15), а не 3.0: третья мажорная версия вышла за две недели до задачи. Обработчики создаются фабрикой `createHandlers(apiBase)` с абсолютным базовым URL. В браузере база — `VITE_API_URL` относительно `location.origin`, в юнит-тестах (`msw/node`) — `http://localhost/api`. Авторизация — заголовок `Authorization: tma <initData>`, иначе 401 `{error: {code: 'unauthorized'}}`.

**Не пускаем моки в прод:** `src/main.tsx` подключает `telegram/mock` и `mocks/browser` динамическим импортом под условиями `import.meta.env.VITE_TG_MOCK === '1'` / `VITE_API === 'mock'`. В продакшен-сборке флаги не заданы (решение 0002), поэтому Vite выкидывает ветки целиком, и в `dist` нет ни MSW, ни фикстур (проверено поиском по `dist`). `mockServiceWorker.js` не копируется в `public/`: в dev его отдаёт плагин `tma80:msw-worker` в `vite.config.ts` прямо из `node_modules/msw`, поэтому версия воркера всегда совпадает с установленной библиотекой.

**RTK Query:** `src/api/api.ts` — `createApi` с `fetchBaseQuery` (база `VITE_API_URL`, по умолчанию `/api`; заголовок `Authorization` из `retrieveRawInitData()`). Эндпоинты добавляются через `injectEndpoints`, по файлу на фичу. `POST /auth` сделан query, а не mutation, чтобы результат кешировался и был общим для экранов. Ответ проверяется `responseSchema: authResponseSchema`: RTK Query 2.7+ принимает Standard Schema, а схемы zod 4, включая mini, её реализуют. Store — `src/store/store.ts`.

**e2e:** Playwright 1.64, Chromium с вьюпортом 390 × 844, сценарии в `e2e/`. Конфиг поднимает dev-сервер на отдельном порту 5179 с явными `VITE_TG_MOCK=1 VITE_API=mock`, чтобы не переиспользовать dev-сервер, запущенный с другими флагами. `e2e/` — отдельный TS-проект в `tsc -b`. Из `allowDefaultProject` ESLint убран `*.ts`, потому что `playwright.config.ts` теперь входит в проект `e2e`.

## Альтернативы

- **`@telegram-apps/sdk-react` по букве ТЗ.** Пакет больше не развивается, документация уже про `@tma.js`.
- **Свой мок `window.Telegram.WebApp` без SDK.** Пришлось бы повторять протокол событий, а `mockTelegramEnv` делает это штатно.
- **JSON-фикстуры.** Без типов и без вычисляемых дат; zod-проверка в тесте всё равно нужна.
- **Слаги пользователей (`?user=newbie`).** AGENTS.md и ТЗ говорят `?user=<id>`, и числовой id сразу служит Telegram id.
- **`msw init public/`.** Воркер попал бы в продакшен-статику и мог бы устареть относительно версии msw.
- **MSW 3.0.** Слишком свежий; переход позже — отдельной задачей.

## Последствия

- ТЗ обновлено: в стеке теперь `@tma.js/sdk-react`, а в НФТ «Совместимость» вместо `isVersionAtLeast` указана проверка доступности методов SDK.
- Сервер (задачи 14–16) отвечает на непредвиденные ошибки кодом `internal`.
- Стартовый JS вырос с 68 до ~115 КБ gzip из 200 КБ: `@tma.js/sdk` ~16 КБ, RTK Query + react-redux ~25 КБ, плюс схемы zod/mini. На роутер, экран «Ужин сегодня» и стили остаётся ~85 КБ, поэтому остальные экраны должны грузиться лениво.
- Экранные задачи добавляют схемы ответов в `packages/shared`, эндпоинты через `api.injectEndpoints`, а обработчики — в `createHandlers` в `src/mocks/handlers.ts`. Если обработчику нужно изменяемое состояние (покупки, готовки), его стоит держать в памяти модуля моков.
- Цвет шапки и фона Telegram задан константой в `src/telegram/sdk.ts`. Задача 3 должна брать его из токенов.
- Задачи 15–16 решают, как подписывать initData для `VITE_API=local`.
