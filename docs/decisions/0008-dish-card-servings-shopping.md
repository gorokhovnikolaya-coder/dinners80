# 0008. Карточка блюда: порции, округление, «по вкусу», покупки и пейвол

Дата: 2026-10-10 · Задача: 06

## Контекст

ТЗ (экран 2) задаёт порции 1–8 с пересчётом, «есть дома», корзину и `403 paywall`, но не определяет: порции по умолчанию, правила округления, ингредиенты без количества, срок жизни отметок «есть дома», поведение повторного добавления в покупки и обратную связь, сворачивание списка ингредиентов, метку на карточке и что показывать при `403`, пока пейвола (задача 12) нет. Владелец продукта 2026-10-10 принял рекомендации исполнителя по всем пунктам; правила внесены в ТЗ (экран 2, модель данных, API, «Принятые решения»).

## Решение

**Продуктовые правила (одобрены владельцем):**

- Порции по умолчанию — по «кто ест»: один — 1, пара — 2, семья — 4 (без ответа — 2). Выбранные порции держатся, пока приложение открыто, и переходят в режим готовки.
- Округление пересчитанного количества (`roundAmount`): г и мл — до 10 целые, до 100 шаг 5, от 100 шаг 10, минимум 1; шт, ст. л., ч. л. — шаг 0,5, минимум 0,5; зубчики и щепотки — целые, минимум 1. Шаг выбирается по точному значению, затем округление половины вверх. На базовых порциях — количество из контента без округления.
- Ингредиент «по вкусу»: `amount` и `unit` равны `null` (оба сразу), не пересчитывается, в покупки добавляется без количества.
- Отметки «есть дома» — на сессию (Redux, по блюду), сервер их не хранит.
- Корзина отправляет неотмеченные ингредиенты; сервер заменяет некупленные позиции этого блюда новыми (с новыми порциями), купленные остаются. Пользователь остаётся на карточке, внизу — «Добавлено в список покупок: N» и ссылка «Открыть список». Если всё отмечено «есть дома» — кнопка неактивна.
- Все ингредиенты показываются сразу, без сворачивания.
- Метка как на главном («Новая страна» / «N-е блюдо» / «Уже готовили»); сервер отдаёт её в `GET /dishes/:id`.
- `403 paywall` → переход на `/paywall?dish=<id>` с заменой записи истории; пока задачи 12 нет — временная заглушка: превью из ответа 403 (фото с замком, страна, название), «Откроется с подпиской», «Не сейчас» → назад.

**Технические решения:**

- Логика в `packages/shared`: `defaultServings`, `clampServings`, `roundAmount`, `scaleAmount` (`servings.ts`), `hasCountryAccess` (правило `has_access`), `dishLabel` (метка вынесена из `suggestDishes`). Единицы — `INGREDIENT_UNITS` (`g`, `ml`, `pcs`, `tbsp`, `tsp`, `clove`, `pinch`), отделы — `AISLES`.
- `GET /dishes/:id?servings=` → `dishResponseSchema`: поля карточки, `label`, `baseServings`, `servings` (запрошенные или по «кто ест»; неверное значение отбрасывается), ингредиенты с `baseAmount` (на базовые порции) и `amount` (на `servings`), шаги с плейсхолдерами `{key}` и `timerSeconds`. `403` — `paywallErrorSchema` (`error.preview`: `dishId`, `title`, `countryId`, `countryName`, `imageUrl`).
- Клиент запрашивает блюдо один раз — с порциями, с которыми открывается карточка, — а − / + пересчитывает локально тем же `scaleAmount` из `baseAmount`: без запроса на каждое нажатие, а числа совпадают с серверными.
- `POST /shopping` `{dishId, servings, ingredientKeys}` → `201 {added}`; сервер проверяет доступ к блюду и ключи ингредиентов.
- Слайс `dish` (ленивый, в чанке экрана): `servings` и `atHome` по id блюда; режим готовки (задача 7) читает `selectServings`.
- «Назад» вложенных экранов (`useGoBack`): предыдущий экран приложения или главный, если приложение открыто сразу на этом экране (по `history.state.idx` React Router), — чтобы не выйти из мини-аппа.
- Маршруты `ROUTES.cooking` (`/dishes/:id/cook`, задача 7) и `ROUTES.shopping` (задача 11) объявлены; пока экранов нет, роутер ведёт на главный.
- Мок: рецепты 36 блюд (`mocks/fixtures/recipes.ts`, 2 порции), названия ингредиентов для своих исключений берутся из них; `?mock_error=dish` / `shopping`; список покупок хранится в мок-БД (sessionStorage).

## Альтернативы

- **Запрос на каждое − / +** — точно по контракту API, но задержка и мигание на каждом нажатии; общий `scaleAmount` даёт те же числа без сети.
- **Порции по умолчанию = `base_servings`** — одинаково для всех, но семье пришлось бы каждый раз нажимать «+».
- **Добавлять позиции повторно** — дубли в списке при каждом нажатии корзины.
- **Только навигация на `/paywall` без заглушки** — до задачи 12 пользователь попадал бы на главный экран без объяснения.

## Последствия

- Задача 7: шаги подставляют количества по `{key}` из `scaleAmount` для `selectServings` (или `servings` ответа).
- Задача 11: `GET /shopping` суммирует по `product` + `unit`; позиции «по вкусу» — отдельной строкой без количества.
- Задача 12 заменяет заглушку `screens/paywall/PaywallStubScreen.tsx`; превью берётся из `403` так же.
- Задача 14: `dish_ingredients.amount` и `unit` nullable (оба `null` — «по вкусу»), seed проверяет это вместе с плейсхолдерами и отделами.
- Задача 16: `GET /dishes/:id` и `POST /shopping` повторяют мок-обработчики на общих функциях.
