# 0025. Продакшен: Docker Compose на VPS, TLS от Let's Encrypt, бэкап через rclone, отчёт по метрикам

Дата: 2026-10-17 · Задача: 23

## Контекст

ТЗ («Стек и архитектура», «Хостинг», «Метрики успеха») требует:

- один VPS: nginx с TLS на своём домене, Docker Compose (Postgres, сервер, воркер, nginx);
- ежедневную копию базы и файлов вне VPS;
- проверку доступности из России;
- метрики теста через 14 дней.

Как именно это сделать, ТЗ не говорит. Хвосты прошлых решений:

- 0016: роль базы без прав суперпользователя, seed на проде;
- 0018: раздача фото контента;
- 0019: подключение `media.conf`, бэкап `MEDIA_DIR`;
- 0002: проверка готовности и образ сервера без сборки;
- 0022: `MINI_APP_LINK` и `WEBAPP_URL` на проде.

Продуктовые вопросы согласованы с пользователем 2026-10-17:

- хранилище бэкапов — через rclone, хранить 14 ежедневных копий;
- доступ на тесте не ограничиваем;
- оплата — настоящими Stars, возврат через `payments:refund`;
- определения метрик — ниже;
- на проде seed падает без фото;
- сертификат — Let's Encrypt через certbot, HTTP-01, с автопродлением;
- задача 23 делится на 23a (инфраструктура, агент) и 23b (запуск теста, человек).

## Решение

**Состав** (`deploy/docker-compose.yml`, проект `tma80-prod`, переменные — `deploy/.env` по образцу `deploy/env.example`):

- `postgres` — `postgres:17-alpine`, наружу не открыт;
- `server` — проверка готовности по `/api/health`;
- `worker` — тот же образ `tma80-server`;
- `nginx` — образ `tma80-nginx` со сборкой мини-аппа, единственный публикует порты 80 и 443;
- `certbot` — продлевает сертификаты.

Общие правила:

- Тома: `pgdata`, `media` (у сервера и воркера `/srv/media`, у nginx — только чтение), `certs`, `acme`.
- У всех сервисов логи `json-file` с ротацией 10 МБ × 5.
- Переменные сервера собираются в compose. Отдельные сервисы получают только свои переменные: например, `BOT_TOKEN` не попадает в nginx и rclone.
- `MINI_APP_LINK` = `https://t.me/${BOT_USERNAME}/${APP_SHORT_NAME}`. Из тех же переменных собираются `VITE_BOT_USERNAME` и `VITE_APP_SHORT_NAME`, поэтому клиент и сервер не расходятся (решение 0022).
- `WEBAPP_URL` = `https://${DOMAIN}/`, `PUBLIC_URL` = `https://${DOMAIN}`.

**Образы** (контекст сборки — корень репозитория, `.dockerignore` не пускает `.env*`, `docs/`, `e2e/` и данные):

- `deploy/server.Dockerfile` — `node:24.22-alpine`.
  - Ставятся только продакшен-зависимости `@tma80/server` и `@tma80/shared`; исходники TypeScript запускаются напрямую (решение 0002).
  - `content/` входит в образ — для seed.
  - Процесс работает от пользователя `node`.
- `deploy/web.Dockerfile`:
  - сборка Vite с `VITE_*` из build args, без `dist/.vite`;
  - `nginx:1.28-alpine`;
  - из `content/` копируются только `*.webp`: сами рецепты отдаёт API, за пейволом.

**nginx** (`deploy/nginx/`):

- `nginx.conf` подключает `/etc/nginx/site.conf`.
- Скрипт `40-select-site.sh` при старте выбирает сайт:
  - есть сертификат `DOMAIN` — полный сайт `app.conf`;
  - нет — `acme.conf`: только `/.well-known/acme-challenge/` на порту 80, остальное — 503. Так первый сертификат выпускается тем же HTTP-01 через webroot, что и продления.
- Шаблоны рендерит штатный envsubst образа (`NGINX_ENVSUBST_OUTPUT_DIR=/etc/nginx`, подставляются только заданные переменные).
- Полный сайт:
  - 80 → 301 на https (кроме ACME);
  - TLS 1.2/1.3, HTTP/2, HSTS, `nosniff`;
  - чужое имя или IP — `ssl_reject_handshake`;
  - статика с запасной отдачей `index.html` (без кеша) и `/assets/` на год;
  - `/api/` на `server:3080` через встроенный DNS Docker (`resolver 127.0.0.11`): пересозданный контейнер сервера не ломает прокси;
  - `client_max_body_size 3m` — карточка 2 МБ плюс multipart;
  - `/media/content/<страна>/<slug>.webp` из копии в образе, остальное под `/media/content/` — 404;
  - `media.conf` (решение 0019).
- `X-Frame-Options` не ставится: Telegram Web открывает мини-апп в iframe.
- Раз в 6 часов nginx делает `reload`, чтобы подхватить продлённый сертификат. Образ запускает свой entrypoint только для команды `nginx`, поэтому оболочка вызывает `/docker-entrypoint.sh` сама.

**TLS:**

- `deploy/scripts/init-cert.sh` поднимает nginx в режиме ACME, выпускает сертификат командой `certbot certonly --webroot` и перезапускает nginx уже с полным сайтом. `CERTBOT_STAGING=1` — тестовый УЦ.
- Сервис `certbot` дважды в сутки делает `certbot renew --webroot`.

**База.** `deploy/postgres/initdb/01-app-role.sh` при первом старте с пустым томом создаёт:

- роль `tma80` (`nosuperuser nocreatedb nocreaterole`);
- владеемую ею базу `tma80`.

Сервер, воркер, миграции и seed подключаются ролью `tma80`. Суперпользователь `postgres` нужен только для бэкапа и обслуживания. Пароли — `POSTGRES_PASSWORD` и `APP_DB_PASSWORD`; они попадают в URL, поэтому только буквы и цифры.

**Деплой** (`deploy/scripts/deploy.sh`), по шагам:

1. `compose build`;
2. миграции (`node src/db/migrate.ts`);
3. `node seed/seed.ts --require-photos`;
4. `up -d`.

Флаг `--require-photos` (`npm run db:seed -- --require-photos`) превращает предупреждение о недостающих фото в ошибку контента: блюда без картинки не выходят в прод. Пока фото нет, деплой останавливается на seed, и это ожидаемо.

**Прокси.** `TRUST_PROXY` (`config.ts`) — список доверенных адресов или CIDR для Fastify `trustProxy` в синтаксисе proxy-addr.

- В compose — `uniquelocal`: только nginx доходит до сервера по сети Docker, поэтому `request.ip` и логи показывают адрес клиента.
- Число переходов не принимается: Fastify 5 при числе не доверяет никому.
- nginx перезаписывает `X-Forwarded-For` адресом клиента.

**Бэкап** (`deploy/scripts/backup.sh`, cron хоста раз в сутки):

- Содержимое — `pg_dump --format=custom` суперпользователем и `tar` тома `media` в одном архиве `deploy/backups/tma80-<UTC>.tar`.
- Архив пишется под временным именем `.tar.part` и переименовывается после успеха, поэтому неполный архив не попадает в последние копии. `umask 077` — дамп и фото не читаются другими пользователями хоста.
- Копия уходит на `BACKUP_REMOTE` через `rclone/rclone:1.71.2` в Docker. Конфиг — `deploy/rclone.conf`, в git не попадает; контейнер работает от пользователя, который запустил скрипт.
- Хранятся `BACKUP_KEEP` (14) последних архивов, и локально, и в хранилище. Имена сортируются по времени, лишние удаляются.
- Восстановление — `deploy/scripts/restore.sh <архив> [--yes]`:
  - архив берётся локально или скачивается из хранилища;
  - сервер и воркер останавливаются;
  - база восстанавливается `pg_restore --clean --if-exists --single-transaction`;
  - содержимое `media` заменяется.

**Проверка доступности.** `deploy/scripts/check-availability.sh https://<домен>`:

- запросы: `/` → 200, `/api/health` → 200, несуществующая `/media/share/…` → 404, неподписанная `/media/cooks/…` → 403;
- для каждого запроса — тайминги DNS, TCP, TLS, общий;
- внешний IP сети и срок сертификата.

Скрипт запускают из разных сетей. Порядок проверки — в `docs/deploy.md`.

**Метрики** (`npm run metrics -- --from YYYY-MM-DD [--to YYYY-MM-DD] [--exclude <tg_id>,…]`, `apps/server/src/metrics/`). Даты без времени — полночь по Москве; `--to` не включается, по умолчанию — сейчас. Аккаунты команды (`--exclude`, Telegram id) не входят ни в одну метрику. Приглашения, сделанные командой, тоже не считаются: так набирают тестировщиков.

- **Когорта** — пользователи с `users.onboarded_at` в периоде.
- **Начавшие готовить в первые 7 дней** — у пользователя когорты есть `cook_started` в течение 7 суток после `onboarded_at`; знаменатель — когорта. Цель ≥ 40%.
- **Готовки со штампом** — `cook_finished` / `cook_started`: число событий за период. Цель ≥ 60%.
- **Готовки с фото** — `cooks` с `photo_path` / все `cooks` за период; справочно.
- **2+ блюда за 14 дней** — у пользователя когорты не меньше двух разных `dish_id` в `cooks` за 14 суток после `users.created_at` (регистрации); знаменатель — когорта. Цель ≥ 25%.
- **Приглашённые на активного** — новые за период пользователи с `invited_by` (кроме приглашённых командой), делённые на активных. Активный — хотя бы одна запись в `cooks` за период. Цель ≥ 0.3.
- **Конверсия из показа пейвола в оплату** — по пользователям: знаменатель — пользователи, которым за период хотя бы раз показали пейвол (`paywall_shown`); числитель — те из них, у кого есть `payment_success` не раньше первого показа в периоде и до конца периода. Когорта «завершившие онбординг за период» здесь не применяется: пейвол видят пользователи с 10 странами, обычно пришедшие раньше, поэтому метрика считается по событиям периода, как «Готовки со штампом». Исключаются аккаунты команды; приглашённые командой входят, как и в остальные метрики (иначе выпали бы почти все тестировщики). Цель ≥ 5%.

Отчёт печатает значения с числителем и знаменателем, отметку о цели и число оплат за период. Ещё он сообщает, у скольких пользователей окна 7 и 14 дней ещё не закрылись. Юнит-тесты покрывают разбор аргументов и расчёт, `npm run test:db` — SQL на базе.

## Альтернативы

- **Выпускать первый сертификат через `certbot --standalone`.** Пока порт 80 свободен, это проще. Но в конфиг продления записался бы способ `standalone`, а при работающем nginx он падает. Режим ACME в nginx оставляет один способ — webroot.
- **Traefik или Caddy вместо nginx + certbot.** Они сами выпускают сертификаты, но `secure_link` и шаблон `media.conf` (решение 0019) написаны под nginx, а ТЗ называет nginx.
- **Бэкап отдельным контейнером с cron.** Cron хоста проще: скрипт видит `docker compose`, лог — в файле, его легко запустить руками.
- **restic вместо rclone.** restic даёт шифрование и дедупликацию, но добавляет ещё один пароль и формат репозитория. Шифрование при необходимости даёт удалённое хранилище `crypt` в rclone поверх S3.
- **Именованный том фото против папки хоста.** Том не зависит от UID на хосте; бэкап читает его через `docker compose exec server tar`.
- **Метрики в `packages/shared`.** Это отчёт сервера по SQL, клиенту он не нужен.

## Последствия

- Деплой, DNS, выпуск сертификата, `deploy/.env`, `rclone.conf`, cron бэкапа и запуск `bot:setup` и `payments:refund` на проде делает человек по `docs/deploy.md`. Агент на VPS не ходит.
- Пока в `content/` нет 90 фото, `deploy.sh` останавливается на seed.
- `TERMS_URL` и `PRIVACY_URL` попадают и в бот, и в сборку мини-аппа. После их изменения нужен `deploy.sh`: он пересобирает nginx.
- Задача 23b (человек): доступность из РФ, 20–50 тестировщиков, отчёт `npm run metrics` через 14 дней.
