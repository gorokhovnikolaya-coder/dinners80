# 0016. База: схема Drizzle, миграции, доступ и seed контента

Дата: 2026-10-16 · Задача: 14

## Контекст

ТЗ задаёт таблицы и ключевые поля («Модель данных»), представление `user_countries`, правило `has_access` и проверки seed. Не заданы: драйвер, типы id, способ миграций, формат файлов `content/`, поведение повторного seed. Самого контента в репозитории не было. Пункт «кто готовит 90 рецептов» в ТЗ остаётся открытым.

## Решение

- **Драйвер и ORM.** Используем `drizzle-orm` 0.45 с `node-postgres` (`pg`). `drizzle-kit` только генерирует SQL-миграции (`npm run db:generate`). Применяет их `migrate()` из `drizzle-orm/node-postgres/migrator` (`npm run db:migrate`). `drizzle-kit push` не используем.
- **Схема** — `apps/server/src/db/schema.ts`, 10 таблиц из ТЗ. Колонки в snake_case, поля в коде в camelCase.
  - Id пользователей, ингредиентов, шагов, готовок, покупок, подписок и событий — `uuid` (`gen_random_uuid()`).
  - Id стран — slug (`it`). Id блюд — `<страна>-<slug>` (`it-carbonara`), как в моках.
  - `tg_id` — `bigint`, в коде это `number`: id Telegram помещаются в 2^53.
  - Перечисления — `text` с check-ограничениями. Списки значений берутся из констант `packages/shared` (`HOUSEHOLDS`, `DISH_TAGS`, `CONTINENTS`, `AISLES` и т. д.). Массивы `exclusions` и `tags` проверяются через `<@ array[...]`. Своих исключений не больше `CUSTOM_EXCLUSIONS_MAX`.
  - `dish_ingredients`: `amount numeric` и `unit` — оба `null` или оба заданы, `amount > 0`; `key` уникален в блюде.
  - Целостность через составные внешние ключи: страна готовки совпадает со страной блюда (`cooks(dish_id, country_id)` → `dishes(id, country_id)`), ингредиент покупки принадлежит её блюду (`shopping_items(ingredient_id, dish_id)` → `dish_ingredients(id, dish_id)`).
  - Удаление пользователя каскадно удаляет его данные. В `events` `user_id` становится `null`. Блюдо с готовками удалить нельзя.
  - Значения по умолчанию: `timezone` — `Europe/Moscow` (клиент присылает настоящий в `PATCH /me`), `reminder_time` — 18:00, `reminder_enabled` и `bot_can_write` — `false`.
- **`user_countries` и `has_access`** описаны вручную в миграции `0001_access.sql`: Drizzle Kit не управляет функциями. Миграцию создали командой `drizzle-kit generate --custom`.
  - `user_countries` — `min(created_at)` по паре пользователь + страна в `cooks`.
  - `has_access(user_id, country_id)` — SQL-функция `STABLE`. Возвращает true, если страна пройдена, или пройдено меньше 10 стран, или есть подписка `active` с `expires_at > now()`.
  - Число 10 повторяет `FREE_COUNTRIES_LIMIT`, в SQL рядом стоит комментарий. Та же логика на TypeScript — `hasCountryAccess` в shared.
  - В схеме Drizzle представление объявлено через `pgView(...).existing()`.
- **Формат контента.**
  - `content/<страна>/country.json`: `nameRu`, `continent`, `sort`.
  - `content/<страна>/<slug>.json`: `title`, `level`, `minutes`, `baseServings`, `tags`, `description`, `fact`, `ingredients[]` и `steps[]`.
  - У ингредиента поля `key`, `product`, `name`, `amount`, `unit`, `aisle`. Если `product` не указан, он равен `key`. Для «по вкусу» `amount` и `unit` равны `null`.
  - У шага — `text` и необязательный `timerMinutes`.
  - Папка задаёт id страны, имя файла — slug блюда. Фото лежит по пути `content/<страна>/<slug>.webp`, в `image_path` пишется `<страна>/<slug>.webp`.
  - Схемы — строгие `z.strictObject`: опечатка в имени поля даёт ошибку.
- **Валидация** — чистая `validateContent` в `packages/shared/src/contentFiles.ts`, покрыта юнит-тестами. Она собирает все ошибки сразу, а не только первую. Каждая ошибка указывает файл и правило. Проверки:
  - схемы файлов;
  - плейсхолдер с несуществующим `key` и плейсхолдер ингредиента «по вкусу» (`findStepPlaceholderProblems`);
  - один отдел у одного `product` во всех блюдах;
  - уникальные `key` в блюде;
  - у папки блюда есть `country.json`;
  - уникальный `sort` стран.

  Seed переводит сообщения zod на английский (`z.config(en())`).
- **Seed** (`apps/server/seed/`):
  - Сначала валидирует контент, потом в одной транзакции делает upsert стран и блюд по id.
  - Страны и блюда, которых больше нет в контенте, получают `is_published = false`, а не удаляются: на них ссылаются готовки.
  - Ингредиенты обновляются upsert по (блюдо, `key`), поэтому позиции списков покупок сохраняют ссылку. Удалённые ингредиенты стираются вместе с их позициями. Шаги заменяются целиком.
  - Повторный запуск безопасен (`npm run db:seed`). Если фото нет, выводится предупреждение со счётчиком, seed не падает.
  - `CONTENT_DIR` подменяет папку контента — для тестов и проверки сломанной копии.
- **`db:reset`** работает только с локальной базой: хост `localhost`, `127.0.0.1`, `::1` или Unix-сокет, иначе отказ. Хост определяется тем же парсером, что у `pg` (`pg-connection-string`): учитывается `?host=` в URL и `PGHOST`, если хоста в URL нет; URL с `hostaddr` отклоняется. Сначала валидирует контент: при ошибке база остаётся как была. Потом удаляет схемы `public` и `drizzle`, применяет миграции и запускает seed.
  - `DATABASE_URL` обязателен: npm-скрипты загружают `.env` из корня (`--env-file-if-exists`), без адреса `connect()` падает с понятной ошибкой. Пароля в коде нет; локальное значение — в `.env.example`.
- **Тест базы** `apps/server/src/db/access.test.ts` проверяет `has_access`, `user_countries` и составной ключ `cooks`.
  - Работает в транзакции с откатом.
  - Запускается только командой `npm run test:db` (ставит `TEST_DATABASE=1` и загружает `.env`), поэтому `npm run check` не требует Docker.
  - Строится от `FREE_COUNTRIES_LIMIT`: если константа и число в SQL разойдутся, тест упадёт.
- **Индексы** — на ведущие столбцы внешних ключей, кроме уже покрытых: `cooks(dish_id, country_id)`, `shopping_items(ingredient_id, dish_id)`, `users(invited_by)`, `friendships(friend_id)`; `dishes.country_id` покрыт уникальным `(country_id, slug)`.
- **Роль базы.** Локально сервер подключается владельцем `tma80` из docker-compose — это суперпользователь образа postgres. Отдельную роль без прав суперпользователя для прода (ТЗ, «Модель данных») создаёт задача 23.
- **Контент — черновик** (решение пользователя 2026-10-16). 30 стран × 3 блюда, всё на 2 порции.
  - 36 блюд перенесены из мок-фикстур, 54 написаны агентом по памяти.
  - Фото нет. До закрытого теста рецепты нужно вычитать и проверить готовкой.
  - Раскладка: Европа — it, fr, es, gr, ge, de, pt, hu; Азия — jp, cn, in, th, kr, vn, tr, lb; Америка — pe, ar, br, co, mx, us, cu; Африка и Океания — ma, eg, et, za, ng, au, nz. `sort` идёт в этом порядке.

## Альтернативы

- **`postgres.js`** вместо `pg`. `pg` — самый распространённый драйвер Drizzle, у него есть пул и простая работа с транзакциями. Существенной разницы для MVP нет.
- **Postgres enum** вместо `text` + check. Изменить enum сложнее: значение нельзя удалить. Check-ограничение собирается из тех же констант, что и zod-схемы.
- **`has_access` на TypeScript** в сервере. ТЗ называет это функцией, и SQL-функцию можно звать в запросах выборки, например при пометке закрытых стран. TS-версия `hasCountryAccess` остаётся для моков и клиента.
- **Пересоздавать ингредиенты при каждом seed.** Позиции списков покупок потеряли бы ингредиент.
- **Падать без фото.** Фото пока нет, и это не мешает разработке API.

## Последствия

- Задачи 15–16: запросы пишутся через `connect()` и `Db` из `src/db/client.ts`. Доступ к блюду проверяется `select has_access(...)`. Пройденные страны берутся из `user_countries`. Опубликованность (`is_published`) фильтрует сервер.
- Новая миграция: изменить `schema.ts` → `npm run db:generate` → проверить SQL. Применённые миграции не меняются.
- Если поменяется `FREE_COUNTRIES_LIMIT`, нужна новая миграция с `create or replace function has_access`.
- Задача 17 или 23: раздача фото контента nginx из `content/` или копии. Решить, должен ли seed падать без фото перед закрытым тестом.
- Задача 23: роль без прав суперпользователя, `db:migrate` и `db:seed` на проде. `db:reset` на проде не работает.
