# 0013. Список покупок: суммирование, отметки, очистка, отправка в чат

Дата: 2026-10-11 · Задача: 11

## Контекст

ТЗ (экран 7) задаёт:

- группировку по отделам: мясо и рыба, овощи и зелень, молочное, бакалея, другое;
- суммирование по `product` + единице с перечнем всех блюд;
- отметку «куплено» с зачёркиванием, кнопки «Очистить купленное» и «Отправить список в чат».

ТЗ не определяет:

- как попасть в список (в таб-баре три вкладки);
- где кнопка «Очистить купленное» (в макете её нет);
- пустое состояние;
- как суммировать, если часть позиций продукта куплена;
- чьё название у суммарной строки;
- порядок строк;
- что считать в подписи «куплено X из Y»;
- текст и способ отправки в чат.

Владелец продукта 2026-10-11 принял рекомендации исполнителя по всем пунктам.

## Решение

**Продуктовые правила (одобрены владельцем):**

**Вход**

- На главном экране, в шапке под аватаром, есть кнопка-корзина 44 × 44. Значок показывает число строк, которые осталось купить. Без некупленных строк значка нет.
- Список — вложенный экран с системной «Назад». Вторая точка входа — ссылка «Открыть список» на карточке блюда.

**Строки**

- Суммируются позиции с одинаковым ключом `product` + `unit` + «куплено». Купленные и некупленные позиции одного продукта — разные строки.
- Отметка строки отмечает все её позиции.
- У суммарной строки — название позиции, добавленной первой. Под названием — все блюда через запятую, в порядке добавления, без повторов.
- Ингредиент «по вкусу» — отдельная строка «по вкусу», одна на продукт, со всеми блюдами (как в решении 0008).
- Внутри отдела строки идут по алфавиту. Отмеченная строка остаётся на месте и зачёркивается.
- Отделы — в фиксированном порядке, пустые не показываются.
- Вся строка — `label` чекбокса, высота от 52 px. Тап по названию блюда ничего не открывает.

**Шапка**

- Под заголовком «Покупки» — подпись «N блюд · куплено X из Y»:
  - N — число разных блюд в списке;
  - X и Y считаются по показанным строкам (после суммирования).
- Справа от подписи — текстовая кнопка «Очистить купленное». Она видна, только если есть купленные строки.
- Подтверждения у очистки нет: удаляются только отмеченные позиции.

**Пустой список**

Карточка «Список покупок пуст», под ней «Добавляйте недостающее с карточки блюда — кнопкой корзины». Кнопка «Выбрать ужин» ведёт на главный экран. Нижней кнопки отправки нет.

**Отправка в чат**

- Кнопка «Отправить список в чат» внизу экрана, как в макете.
- Отправка идёт через окно выбора чата Telegram `t.me/share/url` (SDK `shareURL`, как приглашение из решения 0012):
  - в `url` (обязательный параметр) — ссылка-приглашение пользователя в мини-апп;
  - в `text` — только некупленные строки по отделам:

    ```
    Список покупок

    Мясо и рыба
    • Говяжья вырезка — 400 г

    Бакалея
    • Рис — 300 г
    ```

- Если всё куплено, кнопка неактивна.

**Технические решения:**

- **`packages/shared/src/shopping.ts`:**
  - `GET /shopping` → `shoppingResponseSchema`. В `items[]` у каждой позиции: `id`, `dishId`, `dishTitle`, `product`, `name`, `amount` (уже пересчитано `scaleAmount` на порции позиции), `unit`, `aisle`, `checked`, `createdAt`. Позиции идут от старых к новым.
  - `PATCH /shopping/:id` `{checked}` → изменённая позиция (`shoppingItemSchema`).
  - `DELETE /shopping/checked` → `{removed}`.
  - Чистая `buildShoppingList` (юнит-тесты) группирует и суммирует по правилам выше. Суммы округляются до сотых, чтобы `0,1 + 0,2` давало `0,3`, а не двоичный «шум».
  - Ключ строки — id её самой ранней позиции. При отметке строка не пересоздаётся, и фокус клавиатуры остаётся на ней.
- Сервер (задача 16) отдаёт позиции «как есть». Группировку делает клиент той же функцией, сервер может применить её же.
- **Клиент (`src/api/shopping.ts`):**
  - отметка строки отправляет `PATCH` по каждой её позиции;
  - список в кеше RTK Query меняется сразу (оптимистично) и откатывается, если хоть один запрос упал; тогда внизу показывается «Не удалось сохранить отметку. Попробуйте ещё раз.»;
  - очистка убирает купленные позиции из кеша после успешного ответа;
  - корзина на карточке блюда (`POST /shopping`) сбрасывает кеш списка (тег `Shopping`).
- **Счётчик на главном** берётся из того же `GET /shopping` через `buildShoppingList`. Поэтому он совпадает с «X из Y» на экране списка.
- **Мок:**
  - обработчики `GET /shopping` (ключ `?mock_error=shopping_list`), `PATCH /shopping/:id` (`shopping_check`), `DELETE /shopping/checked` (`shopping_clear`);
  - у позиций мок-БД появился `createdAt`;
  - у пользователя 1002 в фикстурах есть готовый список (`mocks/fixtures/shopping.ts`): Ломо сальтадо и Оякодон, рис и соевый соус суммируются, два вида лука идут разными строками, две позиции куплены. У остальных пользователей список пуст.
- Отправка в чат — общая функция `shareToChat` в `telegram/invite.ts`; приглашение (`shareInvite`) теперь использует её.

## Альтернативы

- **Суммировать купленное с некупленным в одну строку** («куплено», только когда отмечены все позиции). Отметка такой строки неоднозначна, а количество к покупке было бы неверным.
- **Четвёртая вкладка «Покупки».** Расходится с макетом: в нём три вкладки.
- **`shareMessage` с подготовленным сообщением.** Нужны бот и сервер (задачи 18/20), а `t.me/share/url` работает уже сейчас.
- **Купленные строки — вниз списка.** Строки прыгали бы под пальцем при отметке.

## Последствия

- Задача 16: эндпоинты `/shopping` на сервере. `GET` пересчитывает количества через `scaleAmount` на `shopping_items.servings`. `PATCH` и `DELETE` проверяют владельца позиции. Ответы — по схемам из `packages/shared`.
- `POST /shopping` по-прежнему заменяет некупленные позиции блюда; купленные остаются отдельными строками до очистки.
- Длинный список упирается в лимит длины сообщения Telegram (4096 символов). При 90 рецептах и нескольких блюдах в списке до него далеко. Если понадобится — обрезать текст с пометкой.
