# ТЗ: Вокруг света за 80 ужинов — Telegram Mini App (MVP)

Oct 8, 2026 · @Nikolay

## Цель и продукт

Делаем Telegram Mini App, который каждый вечер отвечает на вопрос «что приготовить на ужин» и превращает готовку в путешествие: за первое блюдо новой страны пользователь получает штамп в паспорт, а страна закрашивается на карте мира.

- **Аудитория:** русскоязычные пользователи Telegram 22–40 лет, которые готовят дома 3+ раза в неделю и устают выбирать, что приготовить.
- **Ценность:** выбор ужина за 10 секунд; проверенные рецепты из продуктов обычного супермаркета; азарт коллекции и соревнования с друзьями.
- **Контент MVP:** 30 стран × 3 блюда (будний вечер, выходные, вызов) = 90 рецептов.
- **Монетизация:** подписка в Telegram Stars. Бесплатно — первые 10 стран.
- **Цель MVP:** проверить, что люди готовят повторно, зовут друзей и платят. Пороговые значения — в разделе «Аналитика и метрики успеха».

## Пользователи и сценарии

Пять сценариев покрывают весь MVP; основной — ежедневный ужин.

1. **Первый вход.** Пользователь открывает мини-апп по ссылке → отвечает на 3 вопроса онбординга → сразу видит предложения на ужин, без регистрации.
2. **Ежедневный ужин.** Вечером открывает приложение (или получает напоминание от бота) → выбирает одну из 3 карточек → добавляет недостающее в список покупок → готовит по шагам → фотографирует блюдо (по желанию) → получает штамп.
3. **Приглашение друга.** Делится карточкой штампа или ссылкой-приглашением → друг открывает мини-апп по ссылке (новый или уже зарегистрированный пользователь) → оба видят друг друга в рейтинге.
4. **Оплата.** Открывает блюдо из 11-й новой страны → видит пейвол → платит в Stars → получает доступ ко всем странам.
5. **Возврат к прогрессу.** Открывает карту, смотрит пройденные страны, выбирает блюдо из конкретной страны.

## Объём MVP

В MVP входит только цикл «ужин → готовка → штамп → поделиться» и оплата; всё остальное откладываем до проверки удержания.

**Входит:**

- Онбординг из 3 вопросов
- Экран «Ужин сегодня»: 3 предложения, переключатель «Будни / Выходные»
- Карточка блюда: порции, отметка «есть дома», добавление в список покупок
- Режим готовки: один шаг на экране, таймеры
- Фото блюда, штамп, карточка для шаринга
- Карта и паспорт: страны по континентам
- Друзья: рейтинг, лента штампов, приглашение
- Список покупок по отделам магазина
- Пейвол и подписка в Stars
- Профиль и настройки: ответы онбординга, напоминания, подписка
- Бот: запуск мини-аппа, приглашения, счета, напоминания об ужине
- Загрузка контента (90 рецептов) из файлов репозитория в базу

**Не входит:**

- Подбор блюд по продуктам из холодильника
- Командный режим (общая карта пары или семьи)
- Сезонные челленджи
- Лайки и комментарии
- Рецепты от пользователей
- Автоматическая модерация фото
- Другие языки, кроме русского
- Веб-версия вне Telegram (кроме режима разработки)

## Экраны и функциональные требования

В приложении 10 экранов, внешний вид — по [макету экранов](https://claude.ai/artifact/7CiZksb4DEdHmmUus8G2Mn). Навигация: нижняя панель из 3 вкладок (Ужин, Карта, Друзья); профиль открывается по аватару в шапке экрана «Ужин сегодня»; на вложенных экранах — системная кнопка «Назад» Telegram.

Для экранов с загрузкой данных обязательны три состояния: загрузка (скелетон), ошибка с кнопкой «Повторить», пустое состояние, если оно возможно.

### 0. Онбординг

- Показывается один раз, при первом входе. 3 шага: кто ест (один / пара / семья с детьми), время на ужин в будни (20 / 30 / 45 мин), что не ест (мясо, острое, глютен — множественный выбор, можно ничего; свинина — это мясо, отдельного варианта нет) и поле «Своё» — свои исключения свободным текстом (например, «кинза»), до 10 слов по 2–40 символов.
- Онбординг светлый, фон и шапка Telegram — как у всего приложения и скелетона загрузки, чтобы при входе фон не менялся. Вариант «Семья с детьми» острое не исключает.
- Прогресс-бар из 3 сегментов, кнопка «Дальше». Ответы сохраняются в профиль; потом их можно изменить в настройках.
- После последнего шага — сразу экран «Ужин сегодня».

### 1. Ужин сегодня (главный)

- Сверху: дата, заголовок «Что на ужин сегодня?», аватар (44 px, фото из Telegram или первая буква имени; тап → Профиль) и плитка счётчика «N / 30 стран» (тап → Карта; знаменатель — число опубликованных стран).
- Переключатель «Будни · до N мин / Выходные». Будни — блюда уровня «будний вечер» не дольше выбранного времени; выходные — уровни «выходные» и «вызов». При открытии выбран режим по дню недели в часовом поясе пользователя: пн–пт — «Будни», сб–вс — «Выходные»; выбор переключателя держится, пока приложение открыто.
- 3 карточки: одна большая, две маленькие. Большая: фото с меткой, страна, название, время и уровень (без чипа порций). Маленькая: фото, «СТРАНА · МЕТКА», название, «25 мин · Вызов». Метки: «Новая страна» — страна не пройдена; «N-е блюдо» — N = число разных приготовленных блюд этой страны + 1; «Уже готовили» — это блюдо пользователь уже готовил.
- Кнопка «Показать другие» — следующие 3 предложения; скрыта, если блюд 3 или меньше.
- **Алгоритм подбора:** исключить блюда с тегами из запретов пользователя и блюда, в названии или в названиях ингредиентов которых встречается одно из своих исключений пользователя (подстрока без учёта регистра, ё = е, пробелы по краям обрезаются); сначала блюда из непройденных стран, затем непробованные блюда пройденных стран, затем повторы блюд, приготовленных больше 14 дней назад; не повторять блюда, приготовленные за последние 14 дней; при равенстве — случайный порядок, одинаковый в течение дня (seed = дата по часовому поясу пользователя + user\_id).
- **Если блюд не хватает** на страницу (жёсткие запреты, короткое время, всё приготовлено недавно), ограничения ослабляются по очереди и только до заполнения страницы, по одному блюду: сначала снимается правило 14 дней (самые давние готовки первыми), затем в режиме «Будни» добавляются блюда дольше выбранного времени (ближайшие по времени первыми). Запреты пользователя (теги и свои исключения) не ослабляются никогда. Если блюд всё равно меньше 3 — показываем сколько есть.
- «Показать другие» листает выдачу по кругу: после последней страницы — снова первая; неполная последняя страница добирается блюдами с начала выдачи. На одной странице по возможности нет двух блюд одной страны (блюдо поднимается выше по выдаче только ради этого).
- **Пустое состояние** (запреты отсекли все блюда режима): «Под ваши ограничения блюд не нашлось» и кнопка «Изменить исключения» → Профиль.
- **Бесплатный пользователь с 10 пройденными странами** (без действующей подписки, в том числе после её окончания): большая и первая маленькая карточки — доступные блюда (непробованные блюда пройденных стран, затем повторы); третья карточка — блюдо новой страны с замком: затемнённое фото с замком, страна, название, «Откроется с подпиской». Карточка с замком подчиняется режиму и листается вместе с «Показать другие»; если подходящего блюда новой страны нет — 3 доступные карточки. Тап по карточке с замком ведёт сразу на пейвол.

### 2. Карточка блюда

- Фото, страна, метка (как на главном: «Новая страна» / «N-е блюдо» / «Уже готовили»), название, описание, интересный факт.
- Время, уровень, порции (− / +, от 1 до 8). При смене порций количества ингредиентов пересчитываются. Порции при открытии — по «кто ест»: один — 1, пара — 2, семья — 4; выбранные порции держатся, пока приложение открыто, и переходят в режим готовки.
- **Округление** пересчитанных количеств: г и мл — до 10 целые, до 100 с шагом 5, от 100 с шагом 10; шт, ст. л., ч. л. — с шагом 0,5 (не меньше 0,5); зубчики и щепотки — целые (не меньше 1). Ингредиент «по вкусу» не пересчитывается.
- Ингредиенты с чекбоксом «есть дома», все сразу, без сворачивания; отметки держатся, пока приложение открыто. Кнопка корзины добавляет неотмеченные ингредиенты в список покупок: некупленные позиции этого блюда заменяются новыми (без дублей), пользователь остаётся на карточке и видит «Добавлено в список покупок: N» со ссылкой «Открыть список». Если всё отмечено «есть дома» — кнопка неактивна.
- Кнопка «Начать готовить» → режим готовки.
- Закрытая страна (`403 paywall`) — карточка не открывается, сразу пейвол (с заменой записи в истории).

### 3. Режим готовки

- Один шаг на экране, крупный шрифт (не меньше 20 px), прогресс «3 / 6». Количества ингредиентов подставлены в текст шага с учётом порций: плейсхолдер `{key}` заменяется только количеством («400 г»), существительное в нужном падеже автор пишет в тексте шага после него («Обжарьте {beef} говядины» → «Обжарьте 400 г говядины»). Подсказок к шагам в MVP нет.
- Внизу — «Назад» (предыдущий шаг, на первом неактивна) и «Следующий шаг»; системная кнопка «Назад» Telegram возвращает на карточку блюда без подтверждения. Текущий шаг и таймеры держатся, пока приложение открыто: «Начать готовить» продолжает с того же шага.
- Если у шага есть время — кнопка таймера: запуск, пауза, продолжение, сброс. У каждого шага свой таймер, идти могут несколько сразу; таймер продолжает считать при переходе между шагами (идущие таймеры других шагов видны строкой «Шаг 2 · 12:34», нажатие открывает шаг), по окончании — вибрация и звук и надпись «Время вышло». Если таймер закончился, пока пользователь был вне режима, сигнала нет — при возврате видно «Время вышло».
- Экран не гаснет, пока открыт режим (Screen Wake Lock, где поддерживается).
- Свайпы вертикального закрытия мини-аппа отключены, чтобы не закрыть приложение мокрыми руками.
- На последнем шаге — кнопка «Готово!» → экран фото и штампа; шаг и таймеры этого блюда сбрасываются.

### 4. Фото и штамп

- Экран открывается только по «Готово!» в режиме готовки; прямой вход по ссылке или перезагрузка ведут на карточку блюда, чтобы готовка не записалась дважды.
- Сначала экран (светлый) предлагает сфотографировать блюдо: «Сфотографируйте блюдо», «Фото увидите вы и ваши друзья»; главная кнопка «Сфотографировать» (камера или галерея, обычный input type=file), второстепенная — «Без фото». Фото не обязательно: штамп даётся в обоих случаях. Готовка записывается (`POST /cooks`) после выбора: с фото — после его загрузки, иначе — сразу. Ушёл с экрана без выбора (системная «Назад» — на карточку) — готовка не засчитывается.
- Перед загрузкой фото сжимается на клиенте (см. «Нефункциональные требования»). Если загрузка не удалась — «Не удалось загрузить фото» и выбор: «Повторить» или «Продолжить без фото»; готовка всё равно засчитывается. Ошибка записи — «Не удалось сохранить готовку» и «Повторить»; дневной лимит — «Сегодня уже 20 готовок — это дневной лимит. Попробуйте завтра» и «На главную»; `403` — пейвол.
- Без фото карточка для шаринга использует фото блюда из контента; в ленте друзей запись показывается без снимка.
- Результат — тёмный (navy) экран по макету; шапка и фон Telegram на время экрана тоже navy. Если страна новая — «Новая страна!», фото со штампом («Вокруг света», страна, дата по часовому поясу пользователя) и анимацией, вибрация, «Перу в паспорте», «Ломо сальтадо · 13-е блюдо», «8 из 30 стран» с прогресс-баром и «+1 сегодня». Если страна уже пройдена — «Блюдо засчитано», название блюда, «Перу · 13-е блюдо», прогресс без «+1», без штампа и вибрации. N в «N-е блюдо» — все готовки пользователя, включая повторы. Фото — снимок пользователя, без него — фото блюда из контента.
- Строка про рейтинг, если пользователь обогнал друга: «Жанна теперь позади вас в рейтинге друзей» (имя в именительном падеже — склонять имена из Telegram надёжно нельзя).
- Кнопка «Открыть карту» → карта. Системная «Назад» с экрана результата — на главный.
- Кнопка «Поделиться карточкой»: картинка с фото блюда, штампом и счётчиком стран. Картинку рисует клиент (canvas, 1080 × 1920 для истории) и загружает на сервер в публичную папку `share` (см. «Интеграция с Telegram»).

### 5. Карта и паспорт

- Заголовок «Мой паспорт» и число блюд («13 блюд» — все готовки, включая повторы); крупный счётчик «8 / 30» (знаменатель — число опубликованных стран) и прогресс-бар.
- Страны сгруппированы по континентам, у каждой группы счётчик «3 из 8». Континенты — фиксированный список в фиксированном порядке: Европа, Азия, Америка, Африка и Океания; пустые не показываются; страны внутри группы — по порядку контента, а не по прохождению. Пройденная страна залита цветом, непройденная — пунктир, закрытая для пользователя — пунктир с замком. Отдельного пустого состояния нет: у новичка «0 / 30» и все страны пунктиром.
- Тап по стране → вложенный экран страны (системная «Назад» — на карту): континент, название, статус («В паспорте с 12 октября» — дата первого штампа по часовому поясу пользователя / «Ещё не пройдена» / «Откроется с подпиской») и её 3 блюда: фото, название, «25 мин · Будний вечер», отметка «Приготовлено». Тап по блюду — карточка блюда. Если страна закрыта для пользователя — блюда с замком, тап ведёт на пейвол.

### 6. Друзья

- Рейтинг друзей по числу стран (при равенстве — по числу блюд, затем по имени; при равенстве стран и блюд место общее: 1, 2, 2, 4), переключатель «Эта неделя / Всё время» (при открытии — «Эта неделя», выбор помнится, пока приложение открыто). Пользователь всегда виден в списке — строка «Вы»; у каждого — «N блюд» за выбранный период.
- «Эта неделя» — новые страны (первые штампы) и все приготовленные блюда за текущую неделю. Неделя считается с понедельника 00:00 по часовому поясу того, кто смотрит рейтинг, для всех участников одинаково.
- Лента последних штампов друзей (до 20 записей): штамп — первая готовка друга в стране, повторы не показываются. Запись: «**Маша** — Грузия в паспорте», ниже «Хачапури по-аджарски · 2 ч назад» («только что», «N мин назад», «N ч назад», «вчера», дальше дата); фото друга или, без фото, нейтральная плитка со штампом. Штампов нет — «У друзей пока нет штампов».
- Кнопка «Позвать друга в Telegram» — отправка ссылки-приглашения через выбор чата Telegram (`t.me/share/url`) с текстом «Готовлю ужины из кухонь разных стран и собираю штампы в паспорт. Присоединяйся — посоревнуемся!».
- Пустое состояние (друзей нет): «Позовите друзей, чтобы соревноваться» + кнопка приглашения; рейтинг и лента не показываются.

### 7. Список покупок

- Продукты сгруппированы по отделам: мясо и рыба, овощи и зелень, молочное, бакалея, другое. У каждого — количество и блюдо, для которого он нужен.
- Одинаковые продукты из разных блюд суммируются, если совпадают ключ продукта (`product`, см. «Модель данных») и единица измерения; у суммы показываются все блюда. Разные единицы одного продукта — отдельные строки.
- Отметка «куплено» зачёркивает пункт. Кнопка «Очистить купленное».
- Кнопка «Отправить список в чат» — текстом через шаринг Telegram.

### 8. Пейвол

- Показывается при открытии блюда закрытой страны (тап по карточке с замком на главном экране или на карте) и из профиля. Карточка закрытого блюда не открывается: рецепт виден только после оплаты.
- Экран тёмный (navy) по макету; шапка и фон Telegram на время экрана тоже navy.
- Мини-карта с пройденными странами (плитка на каждую опубликованную страну, пройденные залиты), заголовок «N стран позади. Ещё 30 − N ждут вас» (N — число пройденных стран, 30 — число опубликованных; глагол согласуется с числом: «Ещё 21 ждёт вас»). Без пройденных стран — «30 стран ждут вас», все пройдены — «Все 30 стран позади».
- Подзаголовок: с блюда — «Марокко откроется с подпиской. Ваш паспорт и штампы останутся с вами.» (название страны в именительном падеже — склонять его надёжно нельзя), из профиля — «С подпиской откроются все страны. Ваш паспорт и штампы останутся с вами.».
- 3 преимущества: «Все 30 стран и 90 проверенных рецептов» (числа — опубликованные страны и блюда), «Новые страны в ежедневной подборке ужинов», «Весь паспорт: штампы всех 30 стран».
- Два тарифа, цены в Stars — константы в `packages/shared`: год — 1200 Stars, «≈ 100 Stars в месяц», метка «Выгоднее», выбран по умолчанию; месяц — 150 Stars, «Продлевается каждые 30 дней». Кнопка «Продолжить путешествие» открывает счёт Telegram на выбранный тариф.
- Статусы счёта: `cancelled` — без сообщения, тарифы остаются; `failed` — «Оплата не прошла. Попробуйте ещё раз»; `pending` — «Платёж обрабатывается. Подписка включится, как только Telegram его подтвердит» и кнопка «Обновить» (перепроверить подписку); `paid` — «Подтверждаем оплату…»: сервер узнаёт о платеже из вебхука, поэтому клиент около 15 секунд перепроверяет подписку; не дождался — «Оплата прошла, подписка включится в течение минуты» и «Обновить». Счёт не создался — «Не удалось открыть оплату» и «Повторить».
- После успешной оплаты — возврат к блюду, которое пользователь хотел открыть (карточка блюда с заменой записи в истории); из профиля — пейвол в состоянии «подписка активна».
- «Не сейчас» и системная «Назад» закрывают пейвол; прогресс и штампы сохраняются. Крестика нет.
- Если подписка уже активна, вместо тарифов показывается срок её действия: подзаголовок «Подписка открыла все страны.», «Подписка активна до 5 ноября», кнопка «Продолжить путешествие» закрывает пейвол, «Не сейчас» нет. Про автопродление не пишем: сервер не знает, отключил ли его пользователь в Telegram.

### 9. Профиль и настройки

- Светлый вложенный экран «Профиль» без нижней панели, системная «Назад» — на предыдущий экран. Порядок блоков: шапка → напоминание → подписка → ответы онбординга → документы. Макета экрана нет: он собран из компонентов остальных экранов.
- Аватар и имя из Telegram, под именем — @username (если есть), счётчики стран и блюд («8 из 30 стран», «13 блюд» — все готовки; не нажимаются).
- Ответы онбординга: «Кто ест», «Время на ужин в будни», «Что не едите» (теги и свои исключения) — редактируются теми же контролами, что в онбординге. «Изменить исключения» на главном открывает профиль на блоке «Что не едите».
- Любое изменение сохраняется сразу (`PATCH /me`), без кнопки «Сохранить»; своё исключение добавляется кнопкой «Добавить» или Enter. Если сохранить не удалось — значение откатывается, внизу «Не удалось сохранить. Проверьте интернет и попробуйте ещё раз.» и «Повторить».
- Напоминание об ужине: переключатель «Напоминание об ужине» с подписью «Бот пришлёт идею ужина в выбранное время» и время «Время» (список с шагом 30 минут, 00:00–23:30, по умолчанию 18:00; при выключенном напоминании скрыто). Переключатель показывает фактическое состояние: включён, только если напоминание включено и бот может писать пользователю. При включении, если бот ещё не может писать пользователю, запрашивается разрешение (`requestWriteAccess`); при отказе переключатель остаётся выключенным, без сообщения. В клиенте без `requestWriteAccess` переключатель неактивен, под ним «Обновите Telegram, чтобы включить напоминания».
- Подписка: действует — «Подписка активна до 5 ноября», без кнопки; не было — «Бесплатно — 10 стран на выбор»; закончилась — «Подписка закончилась 5 ноября»; в обоих последних случаях кнопка «Открыть все страны» → пейвол.
- «Документы»: ссылки «Условия использования» и «Политика конфиденциальности» на внешние страницы (адреса — переменные сборки), открываются через `openLink` в Instant View, вне Telegram — в новой вкладке. Без адресов в продакшен-сборке ссылки скрыты.

## Модель данных

База — Postgres на VPS, 10 таблиц. Штамп не хранится отдельно: страна считается пройденной, если у пользователя есть хотя бы одна запись в `cooks` с блюдом этой страны.

| Таблица | Ключевые поля | Назначение |
| --- | --- | --- |
| `users` | `id` uuid, `tg_id` bigint unique, `first_name`, `username`, `photo_url`, `household` (solo / couple / family), `weekday_minutes` (20 / 30 / 45), `exclusions` text\[\] (meat / spicy / gluten), `custom_exclusions` text\[\] (свои исключения: до 10 слов по 2–40 символов, хранятся очищенными — без лишних пробелов, в нижнем регистре, без повторов), `timezone` (IANA, например `Europe/Moscow`), `reminder_enabled` bool, `reminder_time` time (по умолчанию 18:00), `bot_can_write` bool, `invite_code` unique, `invited_by` → users, `onboarded_at`, `created_at`, `last_seen_at` | Профиль, настройки онбординга и напоминаний |
| `countries` | `id` (slug, например `pe`), `name_ru`, `continent`, `sort`, `is_published` | 30 стран |
| `dishes` | `id`, `country_id` → countries, `slug`, `title`, `level` (weekday / weekend / challenge), `minutes`, `base_servings`, `description`, `fact`, `image_path`, `tags` text\[\] (meat, spicy, gluten; блюдо со свининой помечено `meat` — свинина тоже мясо, отдельного тега нет), `is_published` | 90 блюд |
| `dish_ingredients` | `id`, `dish_id`, `key` (уникален в рамках блюда, например `onion`), `product` (общий ключ продукта для суммирования покупок, например `onion`), `name`, `amount` numeric (nullable), `unit` (g / ml / pcs / tbsp / tsp / clove / pinch, nullable; `amount` и `unit` оба `null` — «по вкусу»), `aisle` (meat / veg / dairy / grocery / other), `sort` | Ингредиенты на `base_servings` |
| `dish_steps` | `id`, `dish_id`, `n`, `text` (с плейсхолдерами `{key}` ингредиентов этого блюда), `timer_seconds` | Шаги рецепта |
| `cooks` | `id`, `user_id`, `dish_id`, `country_id`, `photo_path` (nullable — фото необязательно), `created_at` | Факт приготовления; повторы разрешены |
| `friendships` | `user_id`, `friend_id`, `created_at`; первичный ключ из пары | Связь друзей, две записи на пару |
| `shopping_items` | `id`, `user_id`, `ingredient_id`, `dish_id`, `servings`, `checked`, `created_at` | Список покупок |
| `subscriptions` | `id`, `user_id`, `plan` (month / year), `stars_amount`, `telegram_payment_charge_id` unique, `is_recurring` bool, `starts_at`, `expires_at`, `status` (active / expired / refunded) | Оплаты в Stars; одна запись на каждый платёж, включая продления |
| `events` | `id`, `user_id`, `name`, `props` jsonb, `created_at` | Продуктовая аналитика |

Представления и правила:

- `user_countries` — пройденные страны пользователя с датой первого штампа.
- `has_access(user, country)` — true, если страна уже пройдена, или у пользователя меньше 10 пройденных стран, или есть действующая подписка. Бесплатные 10 стран — любые на выбор пользователя.
- Действующая подписка — запись со статусом `active` и `expires_at` в будущем. Если пользователь отключил продление в Telegram, следующий платёж просто не придёт, и доступ закончится по `expires_at`. `refunded` доступ не даёт. После окончания подписки пройденные страны остаются открытыми.
- Клиент не подключается к базе: и чтение, и запись идут только через API Node-сервера, который проверяет пользователя и права. Сервер подключается к базе отдельной ролью без прав суперпользователя; порт Postgres наружу не открыт.
- Контент хранится в репозитории в `content/` (по файлу на блюдо) и загружается в базу seed-скриптом. Seed-скрипт валидирует файлы zod-схемой и падает с понятной ошибкой, если в шаге есть плейсхолдер с несуществующим `key` или с ингредиентом «по вкусу» (без количества), или у одного `product` в разных блюдах разные отделы. Плейсхолдер `{key}` в тексте шага заменяется только количеством с единицей («400 г»), поэтому автор пишет после него существительное в нужном падеже: «Обжарьте {beef} говядины».

## API и серверная логика

Вся логика с правами доступа — в Node-сервере; клиент вызывает его по пути `/api` на своём домене (nginx проксирует запросы на сервер, см. «Стек и архитектура») с заголовком `Authorization: tma <initData>`, сервер проверяет подпись и находит пользователя. Пути в таблице — относительно `/api`. Ответы — JSON, схемы описаны в `packages/shared` (zod) и общие для клиента и сервера.

| Метод и путь | Что делает |
| --- | --- |
| `POST /auth` | Проверяет initData, создаёт или обновляет пользователя, обрабатывает `start_param` (приглашение), возвращает профиль, статус подписки и флаг «нужен онбординг» |
| `PATCH /me` | Сохраняет настройки онбординга (в том числе свои исключения), напоминаний и часовой пояс |
| `GET /home?mode=weekday\|weekend&page=0` | 3 предложения по алгоритму подбора + счётчики стран и блюд |
| `GET /dishes/:id?servings=2` | Блюдо с меткой, ингредиентами и шагами, пересчитанными на порции (без `servings` — по «кто ест»). Если доступа нет — `403` с кодом `paywall` и кратким превью (страна, название, фото) без ингредиентов и шагов |
| `GET /map` | Страны по континентам с отметкой «пройдена» и списком блюд |
| `POST /uploads/cook-photo` | Принимает сжатое фото (multipart), сохраняет в приватную папку `cooks`, возвращает `photo_path` |
| `POST /cooks` | Фиксирует приготовление (`dish_id`, `photo_path` необязателен, только из папки этого пользователя); проверяет доступ и лимит; возвращает `{cookId, newCountry, countriesCount, countriesTotal, dishesCount, overtook}` |
| `PATCH /cooks/:id` | Добавляет фото к уже записанной готовке (если загрузка прошла позже) |
| `GET /friends/leaderboard?period=week\|all` | Рейтинг друзей и пользователя |
| `GET /friends/feed` | Последние 20 штампов друзей |
| `GET /shopping`, `POST /shopping`, `PATCH /shopping/:id`, `DELETE /shopping/checked` | Список покупок; `POST` добавляет ингредиенты блюда на порции, заменяя его некупленные позиции |
| `POST /payments/invoice` | Создаёт ссылку на счёт в Stars для тарифа `month` или `year` |
| `POST /uploads/share-card` | Принимает картинку карточки (multipart) своей готовки (`?cookId=`), сохраняет в публичную папку `share`, возвращает её публичный URL; одна карточка на готовку — повторная загрузка возвращает тот же URL |
| `POST /share/stamp/:cookId` | Сохраняет подготовленное inline-сообщение (`savePreparedInlineMessage`) с картинкой карточки и ссылкой-приглашением, возвращает его id для `shareMessage` |
| `POST /bot/webhook` | Вебхук бота: `/start`, `pre_checkout_query`, `successful_payment`; запрос принимается только с верным заголовком `X-Telegram-Bot-Api-Secret-Token` |
| `POST /events` | Пачка аналитических событий |

Правила сервера:

- **Доступ к блюду** проверяется в `GET /dishes/:id` и повторно в `POST /cooks` по правилу `has_access`. Клиенту не доверяем.
- **Лимит:** не больше 20 записей `cooks` в сутки на пользователя.
- **Фото:** хранятся на диске VPS; приватная папка `cooks`, путь `{user_id}/{uuid}.jpg`. nginx отдаёт их только по подписанным сервером ссылкам на 1 час (модуль `secure_link`); автор и друзья получают такие ссылки в ответах API. Размер загрузки ограничен 500 КБ для фото и 2 МБ для карточки.
- **«Обогнал друга»:** после записи `cooks` сравниваем число стран пользователя до и после с числом стран друзей; обогнан друг, у которого стран было не меньше, чем у пользователя до готовки, и стало меньше, чем после; из нескольких — самый высокий в рейтинге (больше блюд, затем по имени). Возвращаем имя одного друга; повторное блюдо никого не обгоняет.
- **Неделя в рейтинге** — с понедельника 00:00 по часовому поясу пользователя, который запрашивает рейтинг.
- **События оплаты** (`payment_success`) пишет сервер в вебхуке, а не клиент.
- **Ошибки** — единый формат `{error: {code, message}}`; коды (`unauthorized`, `paywall`, `rate_limited`, `not_found`, `validation`) описаны в `packages/shared`.

## Интеграция с Telegram

Telegram даёт нам вход без регистрации, приглашения через ссылки, оплату в Stars и уведомления через бота. Точные названия методов и версии Bot API агент сверяет с актуальной документацией Telegram перед реализацией.

**Авторизация**

- Клиент передаёт сырую строку initData в каждом запросе.
- Сервер проверяет подпись по алгоритму Telegram: секрет = HMAC-SHA256 токена бота с ключом `WebAppData`, затем HMAC-SHA256 отсортированных полей и сравнение с `hash`. Данные старше 24 часов отклоняются.
- Токен бота хранится только на сервере, в переменных окружения (`.env` на VPS, не в git).

**Запуск и приглашения**

- Мини-апп открывается через кнопку меню бота, кнопку в сообщении `/start` и прямую ссылку `t.me/<бот>/<приложение>?startapp=<код>`.
- `startapp` содержит код приглашения пользователя (`users.invite_code`). При любом входе по такой ссылке сервер создаёт дружбу в обе стороны, если её ещё нет и код не принадлежит самому пользователю. `invited_by` записывается только для новых пользователей; событие `invite_joined` — тоже только для новых.

**Оплата в Stars**

- Сервер создаёт ссылку на счёт методом `createInvoiceLink`: валюта `XTR`, пустой `provider_token`, одна позиция с ценой тарифа. Для месячного тарифа используется подписка с периодом 30 дней (`subscription_period`), годовой — разовый платёж на 365 дней.
- Клиент открывает счёт через `openInvoice` и обрабатывает статус: `paid`, `cancelled`, `failed`.
- Вебхук бота отвечает на `pre_checkout_query` (проверка, что тариф и пользователь корректны) и на `successful_payment` записывает подписку. Обработка идемпотентна по `telegram_payment_charge_id`.
- Продление месячной подписки приходит новым `successful_payment` с `is_recurring`; сервер создаёт новую запись, `starts_at` = окончание предыдущего периода, `expires_at` берётся из `subscription_expiration_date`. Любая покупка при действующей подписке (например, годовой тариф при активном месячном) начинается после окончания текущего периода.
- Для возвратов сохраняем `telegram_payment_charge_id`; возврат делается методом `refundStarPayment` вручную администратором, после чего запись получает статус `refunded` и перестаёт давать доступ.
- Для приёма платежей у бота должны быть команды `/terms` и `/paysupport` (требование Telegram).

**Бот**

- `/start` — приветствие и кнопка «Открыть»; с параметром — то же, плюс приглашение.
- Напоминание об ужине: одно сообщение в день в `reminder_time` по часовому поясу пользователя, только при `reminder_enabled` и `bot_can_write`. В сообщении — блюдо дня (первая карточка выдачи «Будни») и кнопка открытия мини-аппа. Управляется в профиле.
- `bot_can_write` становится true, когда пользователь нажал `/start`, разрешил запись в `requestWriteAccess` или пришёл с `allows_write_to_pm` в initData. Если отправка вернула 403 (бот заблокирован), флаг сбрасывается.
- Напоминания по умолчанию включены у тех, кто нажал `/start`; у остальных — выключены до разрешения в профиле.
- Рассылка — по расписанию (процесс-воркер на Node), с соблюдением лимитов Bot API на частоту отправки.

**Интерфейс внутри Telegram**

- При запуске: `ready()`, `expand()`; учёт безопасных отступов (`safeAreaInset`, `contentSafeAreaInset`).
- Системная кнопка «Назад» на вложенных экранах.
- Тактильная отдача (`HapticFeedback`) на штампе и завершении шага.
- В режиме готовки отключаются вертикальные свайпы закрытия.
- Шаринг штампа: история через `shareToStory` (картинка + ссылка-приглашение) и сообщение в чат через подготовленное inline-сообщение (`savePreparedInlineMessage` + `shareMessage`). Если метод не поддерживается клиентом — запасной вариант через `openTelegramLink` на `t.me/share/url`.
- Картинки карточек лежат в публичной папке `share` по пути `{uuid}.jpg` (неугадываемое имя), nginx отдаёт их без подписи; `shareToStory` требует публичный URL. Личные фото из папки `cooks` туда попадают только в составе карточки, которой пользователь сам решил поделиться. Картинки старше 30 дней удаляет воркер.
- Тема в MVP — светлая, фиксированная; цвета Telegram не подхватываем. Чтобы шапка и фон Telegram не остались тёмными, при запуске вызываются `setHeaderColor` и `setBackgroundColor` с цветами из токенов.

## Стек и архитектура

Фронтенд — статическое React-приложение внутри Telegram; бэкенд и бот — Node.js-сервер с Postgres. Всё работает на одном VPS за nginx на своём домене, который стабильно открывается из России; облачных бэкенд-сервисов нет.

**Компоненты**

1. **Мини-апп** — статическая сборка, открывается внутри Telegram.
2. **nginx** — на VPS, единая точка входа на своём домене: TLS, раздача статики мини-аппа, реверс-прокси `/api/*` на Node-сервер, раздача файлов `/media/share/*` (публично) и `/media/cooks/*` (только по подписанной ссылке, `secure_link`).
3. **Node-сервер** — HTTP API для клиента (включая вход по initData) и вебхук бота `/api/bot/webhook`.
4. **Воркер** — отдельный Node-процесс из того же кода: напоминания по расписанию и очистка старых картинок `share`.
5. **Postgres** — на том же VPS, доступен только серверу и воркеру. **Файлы** — на диске VPS: приватная папка `cooks` и публичная `share`.
6. **Telegram** — Bot API (счета, сообщения, prepared messages) и клиент Telegram с SDK мини-аппа.

Клиент никогда не пишет в базу напрямую: каждое действие проходит через функцию, которая проверяет пользователя и права доступа.

**Режим разработки без Telegram**

Агенты и разработчик должны запускать и проверять приложение в обычном браузере.

- `VITE_TG_MOCK=1` — подставное окружение Telegram (SDK умеет `mockTelegramEnv`): тестовый пользователь, тема, безопасные отступы. Набор тестовых пользователей переключается параметром `?user=`.
- `VITE_API=mock` — все запросы обслуживает MSW по фикстурам: 12 стран на 3 континентах, 36 блюд, 3 друга; состояния «новичок», «8 стран», «10 стран без подписки», «10 стран с подпиской», «бот не может писать». Двенадцать стран нужны, чтобы у состояния «10 стран» оставались закрытые страны.
- `VITE_API=local` — локальный Node-сервер и Postgres в Docker с seed-данными; initData подписывается тестовым токеном бота.
- Команда `npm run check` = типы + линтер + юнит-тесты; `npm run e2e` = Playwright по основным сценариям в mock-режиме.

**Хостинг:** всё на одном VPS за nginx на своём домене, который стабильно открывается из России (провайдер VPS — в открытых вопросах). База и файлы копируются в резервное хранилище вне VPS раз в сутки. Перед закрытым тестом доступность проверяется с российских мобильных операторов и домашних провайдеров.

## Нефункциональные требования

**Производительность**

- Первый экран интерактивен за 2 секунды на 4G и телефоне среднего класса.
- Стартовый JS-бандл — не больше 200 КБ в gzip; экраны, кроме главного, грузятся лениво. Размер проверяется в `npm run check` (size-limit); для схем на клиенте используется `zod/mini`.
- Фото блюд из контента — WebP, до 1200 px по длинной стороне, ленивая загрузка.
- Фото пользователя сжимается на клиенте до 1600 px по длинной стороне, JPEG 80%, не больше 500 КБ.
- Рецепт, открытый в режиме готовки, кешируется: при обрыве связи шаги продолжают показываться.

**Безопасность и данные**

- Сервер не доверяет клиенту: штампы, доступ к странам и подписка определяются только на сервере.
- Обработка платежей идемпотентна; повторный вебхук не создаёт вторую подписку.
- Храним минимум данных Telegram: id, имя, username, фото профиля.
- Фото блюд видят только автор и его друзья — кроме карточек, которыми автор сам поделился (папка `share`).
- Секреты (токен бота, пароль базы, ключ подписи ссылок) — только в серверном окружении, не в клиентской сборке.

**Доступность и удобство**

- Контраст текста — не меньше 4.5:1; зоны нажатия — не меньше 44 × 44 px.
- В режиме готовки шрифт шага — не меньше 20 px.
- Кнопки и поля — настоящие элементы `button`, `input`, `label`; у иконок без подписи — `aria-label`.

**Совместимость**

- Telegram для iOS и Android последних двух мажорных версий; Telegram Desktop — базовая работоспособность.
- Методы SDK, которых нет в старой версии клиента, проверяются средствами SDK (`isAvailable` / `ifAvailable` / `supports` — сверяют версию Mini Apps клиента) и имеют запасной вариант.

**Язык**

- Только русский. Все строки интерфейса — в одном файле `src/i18n/ru.ts`, чтобы позже добавить другие языки.

## Принятые решения

- Фото для штампа необязательно; экран настойчиво предлагает его сделать.
- Бесплатные 10 стран — любые на выбор пользователя.
- Пейвол показывается при открытии блюда закрытой страны; рецепт закрыт до оплаты.
- Бесплатный пользователь с 10 странами видит на главном экране 2 доступных блюда и 1 блюдо с замком.
- Бэкенд — свой Node.js-сервер с Postgres на VPS за nginx; Supabase и другие облачные бэкенды не используются. Клиент ходит только на свой домен.
- Время напоминания по умолчанию — 18:00; в онбординге не спрашиваем, меняется в профиле.
- Свинина — это мясо: отдельного варианта и тега нет. Кроме мяса, острого и глютена пользователь может указать свои исключения — они работают как поиск по названию блюда и ингредиентам.
- «Семья с детьми» не исключает острое автоматически.
- Онбординг светлый, как всё приложение.
- «Ужин сегодня» (2026-10-10): режим при открытии — по дню недели пользователя; метки «Новая страна» / «N-е блюдо» (номер блюда внутри страны) / «Уже готовили»; ограничения ослабляются только до заполнения страницы; неполная страница добирается по кругу; на странице по возможности нет двух блюд одной страны; пустое состояние с переходом к исключениям; карточка с замком «Откроется с подпиской»; уровень на маленьких карточках, без чипа порций; аватар слева от счётчика стран (решение 0007).
- «Карточка блюда» (2026-10-10): порции при открытии по «кто ест» (1 / 2 / 4); правила округления; ингредиенты «по вкусу» без количества; «есть дома» — на время сессии; корзина заменяет некупленные позиции блюда и показывает уведомление со ссылкой на список; все ингредиенты без сворачивания; метка как на главном; при `403` — пейвол, до задачи 12 — временная заглушка (решение 0008).
- «Режим готовки» (2026-10-10): `{key}` заменяется только количеством, падеж существительного пишет автор, у ингредиентов «по вкусу» плейсхолдеров нет; подсказок к шагам нет; «Назад» / «Следующий шаг» / «Готово!», системная «Назад» — на карточку, шаг и таймеры держатся, пока приложение открыто; свой таймер у каждого шага (пауза, сброс, строка идущих таймеров, сигнал только в режиме готовки); «Готово!» сбрасывает шаг и таймеры (решение 0009).
- «Фото и штамп» (2026-10-10): экран только после «Готово!»; готовка записывается после выбора «Сфотографировать» (с загрузкой) или «Без фото», без выбора не засчитывается; `PATCH /cooks/:id` в интерфейсе MVP не используется; «N-е блюдо» — все готовки пользователя; результат — navy-экран с перекраской шапки Telegram; «Поделиться карточкой» — с задачей 20; «Открыть карту»; правило «обогнал друга»; тексты экрана, ошибок и лимита (решение 0010).
- «Карта и паспорт» (2026-10-10): шапка «Мой паспорт» и «N блюд» (все готовки); континенты — фиксированный список (Европа, Азия, Америка, Африка и Океания), страны по порядку контента; закрытая страна — пунктир с замком; страна открывается вложенным экраном с датой первого штампа и блюдами («Приготовлено», замки → пейвол); пустого состояния нет (решение 0011).
- «Друзья» (2026-10-11): лента — только штампы (первая готовка в стране), текст без рода «Маша — Грузия в паспорте», без фото — плитка со штампом, относительное время; места при равенстве общие, при открытии «Эта неделя»; без друзей — только приглашение; приглашение — через `t.me/share/url` с одобренным текстом, имя бота и приложения — из переменных сборки (решение 0012).
- «Список покупок» (2026-10-11): вход — корзина со счётчиком некупленного в шапке главного и «Открыть список» на карточке блюда; суммирование по `product` + единице + «куплено» (купленное и некупленное — разные строки), название — первой добавленной позиции, «по вкусу» — отдельной строкой; строки по алфавиту, отмеченные остаются на месте; «N блюд · куплено X из Y» по показанным строкам; «Очистить купленное» — текстовая кнопка у подписи, только при купленных, без подтверждения; пустое состояние с «Выбрать ужин»; «Отправить список в чат» — некупленное по отделам через `t.me/share/url` со ссылкой-приглашением, неактивна, если всё куплено (решение 0013).

- «Пейвол» (2026-10-16): цены — месяц 150 Stars (подписка на 30 дней), год 1200 Stars (≈ 100 Stars в месяц, выбран по умолчанию, метка «Выгоднее»), константы в `packages/shared`; заголовок с согласованием по числу и отдельными вариантами для 0 и всех стран; подзаголовок без склонения названия страны; три преимущества с числами опубликованного контента; тексты статусов оплаты и перепроверка подписки около 15 секунд после `paid`; после оплаты — карточка блюда или состояние «подписка активна»; активная подписка — срок вместо тарифов, без слов об автопродлении; крестика нет, закрывают «Не сейчас» и системная «Назад» (решение 0014).
