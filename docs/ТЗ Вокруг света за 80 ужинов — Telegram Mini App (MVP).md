# ТЗ: Вокруг света за 80 ужинов — Telegram Mini App (MVP)

Oct 8, 2026 · @Nikolay

## Цель и продукт

Делаем Telegram Mini App, который каждый вечер отвечает на вопрос «что приготовить на ужин» и превращает готовку в путешествие: за первое блюдо новой страны пользователь получает штамп в паспорт, а страна закрашивается на карте мира.

- **Аудитория:** русскоязычные пользователи Telegram 22–40 лет, которые готовят дома 3+ раза в неделю и устают выбирать, что приготовить.
- **Ценность:** выбор ужина за 10 секунд; проверенные рецепты из продуктов обычного супермаркета; азарт коллекции и соревнования с друзьями.
- **Контент MVP:** 30 стран × 3 блюда (будний вечер, выходные, вызов) = 90 рецептов.
- **Монетизация:** подписка в Telegram Stars. Бесплатно — первые 10 стран.
- **Цель MVP:** проверить, что люди готовят повторно, зовут друзей и платят. Пороговые значения — в разделе «Аналитика и метрики успеха».

## Пользователи и сценарии

Пять сценариев покрывают весь MVP; основной — ежедневный ужин.

1. **Первый вход.** Пользователь открывает мини-апп по ссылке → отвечает на 3 вопроса онбординга → сразу видит предложения на ужин, без регистрации.
2. **Ежедневный ужин.** Вечером открывает приложение (или получает напоминание от бота) → выбирает одну из 3 карточек → добавляет недостающее в список покупок → готовит по шагам → фотографирует блюдо (по желанию) → получает штамп.
3. **Приглашение друга.** Делится карточкой штампа или ссылкой-приглашением → друг открывает мини-апп по ссылке (новый или уже зарегистрированный пользователь) → оба видят друг друга в рейтинге.
4. **Оплата.** Открывает блюдо из 11-й новой страны → видит пейвол → платит в Stars → получает доступ ко всем странам.
5. **Возврат к прогрессу.** Открывает карту, смотрит пройденные страны, выбирает блюдо из конкретной страны.

## Объём MVP

В MVP входит только цикл «ужин → готовка → штамп → поделиться» и оплата; всё остальное откладываем до проверки удержания.

**Входит:**

- Онбординг из 3 вопросов
- Экран «Ужин сегодня»: 3 предложения, переключатель «Будни / Выходные»
- Карточка блюда: порции, отметка «есть дома», добавление в список покупок
- Режим готовки: один шаг на экране, таймеры
- Фото блюда, штамп, карточка для шаринга
- Карта и паспорт: страны по континентам
- Друзья: рейтинг, лента штампов, приглашение
- Список покупок по отделам магазина
- Пейвол и подписка в Stars
- Профиль и настройки: ответы онбординга, напоминания, подписка
- Бот: запуск мини-аппа, приглашения, счета, напоминания об ужине
- Загрузка контента (90 рецептов) из файлов репозитория в базу

**Не входит:**

- Подбор блюд по продуктам из холодильника
- Командный режим (общая карта пары или семьи)
- Сезонные челленджи
- Лайки и комментарии
- Рецепты от пользователей
- Автоматическая модерация фото
- Другие языки, кроме русского
- Веб-версия вне Telegram (кроме режима разработки)

## Экраны и функциональные требования

В приложении 10 экранов, внешний вид — по [макету экранов](https://claude.ai/artifact/7CiZksb4DEdHmmUus8G2Mn). Навигация: нижняя панель из 3 вкладок (Ужин, Карта, Друзья); профиль открывается по аватару в шапке экрана «Ужин сегодня»; на вложенных экранах — системная кнопка «Назад» Telegram.

Для экранов с загрузкой данных обязательны три состояния: загрузка (скелетон), ошибка с кнопкой «Повторить», пустое состояние, если оно возможно.

### 0. Онбординг

- Показывается один раз, при первом входе. 3 шага: кто ест (один / пара / семья с детьми), время на ужин в будни (20 / 30 / 45 мин), что не ест (мясо, острое, глютен — множественный выбор, можно ничего; свинина — это мясо, отдельного варианта нет) и поле «Своё» — свои исключения свободным текстом (например, «кинза»), до 10 слов по 2–40 символов.
- Онбординг светлый, фон и шапка Telegram — как у всего приложения и скелетона загрузки, чтобы при входе фон не менялся. Вариант «Семья с детьми» острое не исключает.
- Прогресс-бар из 3 сегментов, кнопка «Дальше». Ответы сохраняются в профиль; потом их можно изменить в настройках.
- После последнего шага — сразу экран «Ужин сегодня».

### 1. Ужин сегодня (главный)

- Сверху: дата, счётчик «N из 30 стран» (тап → Карта), аватар (тап → Профиль).
- Переключатель «Будни / Выходные». Будни — блюда уровня «будний вечер» не дольше выбранного времени; выходные — уровни «выходные» и «вызов».
- 3 карточки: одна большая, две маленькие. На карточке фото, страна, название, время, уровень, метка «Новая страна» или «N-е блюдо».
- Кнопка «Показать другие» — следующие 3 предложения.
- **Алгоритм подбора:** исключить блюда с тегами из запретов пользователя и блюда, в названии или в названиях ингредиентов которых встречается одно из своих исключений пользователя (подстрока без учёта регистра, ё = е, пробелы по краям обрезаются); сначала блюда из непройденных стран, затем непробованные блюда пройденных стран; не повторять блюда, приготовленные за последние 14 дней; при равенстве — случайный порядок, одинаковый в течение дня (seed = дата по часовому поясу пользователя + user\_id).
- **Если блюд не хватает** (жёсткие запреты, короткое время, всё приготовлено недавно), ограничения ослабляются по очереди: сначала снимается правило 14 дней (самые давние готовки первыми), затем в режиме «Будни» добавляются блюда дольше выбранного времени (ближайшие по времени первыми). Запреты пользователя (теги и свои исключения) не ослабляются никогда. Если блюд всё равно меньше 3 — показываем сколько есть.
- «Показать другие» листает выдачу по кругу: после последней страницы — снова первая.
- **Бесплатный пользователь с 10 пройденными странами:** большая и первая маленькая карточки — доступные блюда (непробованные блюда пройденных стран, затем повторы); третья карточка — блюдо новой страны с замком. Тап по карточке с замком ведёт сразу на пейвол.

### 2. Карточка блюда

- Фото, страна, название, описание, интересный факт.
- Время, уровень, порции (− / +, от 1 до 8). При смене порций количества ингредиентов пересчитываются.
- Ингредиенты с чекбоксом «есть дома». Кнопка корзины добавляет неотмеченные ингредиенты в список покупок.
- Кнопка «Начать готовить» → режим готовки.

### 3. Режим готовки

- Один шаг на экране, крупный шрифт (не меньше 20 px), прогресс «3 / 6». Количества ингредиентов подставлены в текст шага с учётом порций.
- Если у шага есть время — кнопка таймера; таймер продолжает считать при переходе между шагами, по окончании — вибрация и звук.
- Экран не гаснет, пока открыт режим (Screen Wake Lock, где поддерживается).
- Свайпы вертикального закрытия мини-аппа отключены, чтобы не закрыть приложение мокрыми руками.
- На последнем шаге — кнопка «Готово!» → экран фото и штампа.

### 4. Фото и штамп

- Сначала экран предлагает сфотографировать блюдо: главная кнопка «Сфотографировать» (камера или галерея, обычный input type=file), второстепенная — «Без фото». Фото не обязательно: штамп даётся в обоих случаях.
- Перед загрузкой фото сжимается на клиенте (см. «Нефункциональные требования»). Если загрузка не удалась — предлагаем повторить или продолжить без фото; готовка всё равно засчитывается.
- Без фото карточка для шаринга использует фото блюда из контента; в ленте друзей запись показывается без снимка.
- Если страна новая — анимация штампа, вибрация, текст «Новая страна! Перу — 8 из 30». Если страна уже пройдена — «13-е блюдо», без штампа.
- Строка про рейтинг, если пользователь обогнал друга.
- Кнопка «Поделиться карточкой»: картинка с фото блюда, штампом и счётчиком стран. Картинку рисует клиент (canvas, 1080 × 1920 для истории) и загружает на сервер в публичную папку `share` (см. «Интеграция с Telegram»).

### 5. Карта и паспорт

- Крупный счётчик «8 / 30» и прогресс-бар.
- Страны сгруппированы по континентам, у каждой группы счётчик «3 из 8». Пройденная страна залита цветом, непройденная — пунктир.
- Тап по стране → список её 3 блюд с отметками «приготовлено». Если страна закрыта для пользователя — блюда с замком, тап ведёт на пейвол.

### 6. Друзья

- Рейтинг друзей по числу стран (при равенстве — по числу блюд), переключатель «Эта неделя / Всё время». Пользователь всегда виден в списке.
- «Эта неделя» — новые страны (первые штампы) и все приготовленные блюда за текущую неделю. Неделя считается с понедельника 00:00 по часовому поясу того, кто смотрит рейтинг, для всех участников одинаково.
- Лента последних штампов друзей (до 20 записей).
- Кнопка «Позвать друга в Telegram» — отправка ссылки-приглашения.
- Пустое состояние: «Позовите друзей, чтобы соревноваться» + кнопка приглашения.

### 7. Список покупок

- Продукты сгруппированы по отделам: мясо и рыба, овощи и зелень, молочное, бакалея, другое. У каждого — количество и блюдо, для которого он нужен.
- Одинаковые продукты из разных блюд суммируются, если совпадают ключ продукта (`product`, см. «Модель данных») и единица измерения; у суммы показываются все блюда. Разные единицы одного продукта — отдельные строки.
- Отметка «куплено» зачёркивает пункт. Кнопка «Очистить купленное».
- Кнопка «Отправить список в чат» — текстом через шаринг Telegram.

### 8. Пейвол

- Показывается при открытии блюда закрытой страны (тап по карточке с замком на главном экране или на карте) и из профиля. Карточка закрытого блюда не открывается: рецепт виден только после оплаты.
- Мини-карта с пройденными странами, заголовок «N стран позади. Ещё 30 − N ждут вас» (N — число пройденных стран), 3 преимущества.
- Два тарифа: месяц и год, цены в Stars. Кнопка оплаты открывает счёт Telegram.
- После успешной оплаты — возврат к блюду, которое пользователь хотел открыть.
- «Не сейчас» закрывает пейвол; прогресс и штампы сохраняются.
- Если подписка уже активна, вместо тарифов показывается срок её действия.

### 9. Профиль и настройки

- Аватар и имя из Telegram, счётчики стран и блюд.
- Ответы онбординга: кто ест, время на ужин в будни, что не ест (теги и свои исключения) — редактируются теми же контролами, что в онбординге.
- Напоминание об ужине: переключатель и время (с шагом 30 минут, по умолчанию 18:00). При включении, если бот ещё не может писать пользователю, запрашивается разрешение (`requestWriteAccess`); при отказе переключатель остаётся выключенным.
- Подписка: статус и дата окончания или кнопка «Открыть все страны» → пейвол.
- Ссылки на условия использования и политику конфиденциальности.

## Модель данных

База — Postgres на VPS, 10 таблиц. Штамп не хранится отдельно: страна считается пройденной, если у пользователя есть хотя бы одна запись в `cooks` с блюдом этой страны.

| Таблица | Ключевые поля | Назначение |
| --- | --- | --- |
| `users` | `id` uuid, `tg_id` bigint unique, `first_name`, `username`, `photo_url`, `household` (solo / couple / family), `weekday_minutes` (20 / 30 / 45), `exclusions` text\[\] (meat / spicy / gluten), `custom_exclusions` text\[\] (свои исключения: до 10 слов по 2–40 символов, хранятся очищенными — без лишних пробелов, в нижнем регистре, без повторов), `timezone` (IANA, например `Europe/Moscow`), `reminder_enabled` bool, `reminder_time` time (по умолчанию 18:00), `bot_can_write` bool, `invite_code` unique, `invited_by` → users, `onboarded_at`, `created_at`, `last_seen_at` | Профиль, настройки онбординга и напоминаний |
| `countries` | `id` (slug, например `pe`), `name_ru`, `continent`, `sort`, `is_published` | 30 стран |
| `dishes` | `id`, `country_id` → countries, `slug`, `title`, `level` (weekday / weekend / challenge), `minutes`, `base_servings`, `description`, `fact`, `image_path`, `tags` text\[\] (meat, spicy, gluten; блюдо со свининой помечено `meat` — свинина тоже мясо, отдельного тега нет), `is_published` | 90 блюд |
| `dish_ingredients` | `id`, `dish_id`, `key` (уникален в рамках блюда, например `onion`), `product` (общий ключ продукта для суммирования покупок, например `onion`), `name`, `amount` numeric, `unit`, `aisle` (meat / veg / dairy / grocery / other), `sort` | Ингредиенты на `base_servings` |
| `dish_steps` | `id`, `dish_id`, `n`, `text` (с плейсхолдерами `{key}` ингредиентов этого блюда), `timer_seconds` | Шаги рецепта |
| `cooks` | `id`, `user_id`, `dish_id`, `country_id`, `photo_path` (nullable — фото необязательно), `created_at` | Факт приготовления; повторы разрешены |
| `friendships` | `user_id`, `friend_id`, `created_at`; первичный ключ из пары | Связь друзей, две записи на пару |
| `shopping_items` | `id`, `user_id`, `ingredient_id`, `dish_id`, `servings`, `checked`, `created_at` | Список покупок |
| `subscriptions` | `id`, `user_id`, `plan` (month / year), `stars_amount`, `telegram_payment_charge_id` unique, `is_recurring` bool, `starts_at`, `expires_at`, `status` (active / expired / refunded) | Оплаты в Stars; одна запись на каждый платёж, включая продления |
| `events` | `id`, `user_id`, `name`, `props` jsonb, `created_at` | Продуктовая аналитика |

Представления и правила:

- `user_countries` — пройденные страны пользователя с датой первого штампа.
- `has_access(user, country)` — true, если страна уже пройдена, или у пользователя меньше 10 пройденных стран, или есть действующая подписка. Бесплатные 10 стран — любые на выбор пользователя.
- Действующая подписка — запись со статусом `active` и `expires_at` в будущем. Если пользователь отключил продление в Telegram, следующий платёж просто не придёт, и доступ закончится по `expires_at`. `refunded` доступ не даёт. После окончания подписки пройденные страны остаются открытыми.
- Клиент не подключается к базе: и чтение, и запись идут только через API Node-сервера, который проверяет пользователя и права. Сервер подключается к базе отдельной ролью без прав суперпользователя; порт Postgres наружу не открыт.
- Контент хранится в репозитории в `content/` (по файлу на блюдо) и загружается в базу seed-скриптом. Seed-скрипт валидирует файлы zod-схемой и падает с понятной ошибкой, если в шаге есть плейсхолдер с несуществующим `key` или у одного `product` в разных блюдах разные отделы.

## API и серверная логика

Вся логика с правами доступа — в Node-сервере; клиент вызывает его по пути `/api` на своём домене (nginx проксирует запросы на сервер, см. «Стек и архитектура») с заголовком `Authorization: tma <initData>`, сервер проверяет подпись и находит пользователя. Пути в таблице — относительно `/api`. Ответы — JSON, схемы описаны в `packages/shared` (zod) и общие для клиента и сервера.

| Метод и путь | Что делает |
| --- | --- |
| `POST /auth` | Проверяет initData, создаёт или обновляет пользователя, обрабатывает `start_param` (приглашение), возвращает профиль, статус подписки и флаг «нужен онбординг» |
| `PATCH /me` | Сохраняет настройки онбординга (в том числе свои исключения), напоминаний и часовой пояс |
| `GET /home?mode=weekday\|weekend&page=0` | 3 предложения по алгоритму подбора + счётчики стран и блюд |
| `GET /dishes/:id?servings=2` | Блюдо с ингредиентами и шагами, пересчитанными на порции. Если доступа нет — `403` с кодом `paywall` и кратким превью (страна, название, фото) без ингредиентов и шагов |
| `GET /map` | Страны по континентам с отметкой «пройдена» и списком блюд |
| `POST /uploads/cook-photo` | Принимает сжатое фото (multipart), сохраняет в приватную папку `cooks`, возвращает `photo_path` |
| `POST /cooks` | Фиксирует приготовление (`dish_id`, `photo_path` необязателен); проверяет доступ и лимит; возвращает `{cookId, newCountry, countriesCount, dishesCount, overtook}` |
| `PATCH /cooks/:id` | Добавляет фото к уже записанной готовке (если загрузка прошла позже) |
| `GET /friends/leaderboard?period=week\|all` | Рейтинг друзей и пользователя |
| `GET /friends/feed` | Последние 20 штампов друзей |
| `GET /shopping`, `POST /shopping`, `PATCH /shopping/:id`, `DELETE /shopping/checked` | Список покупок |
| `POST /payments/invoice` | Создаёт ссылку на счёт в Stars для тарифа `month` или `year` |
| `POST /uploads/share-card` | Принимает картинку карточки (multipart), сохраняет в публичную папку `share`, возвращает её публичный URL |
| `POST /share/stamp/:cookId` | Сохраняет подготовленное inline-сообщение (`savePreparedInlineMessage`) с картинкой карточки и ссылкой-приглашением, возвращает его id для `shareMessage` |
| `POST /bot/webhook` | Вебхук бота: `/start`, `pre_checkout_query`, `successful_payment`; запрос принимается только с верным заголовком `X-Telegram-Bot-Api-Secret-Token` |
| `POST /events` | Пачка аналитических событий |

Правила сервера:

- **Доступ к блюду** проверяется в `GET /dishes/:id` и повторно в `POST /cooks` по правилу `has_access`. Клиенту не доверяем.
- **Лимит:** не больше 20 записей `cooks` в сутки на пользователя.
- **Фото:** хранятся на диске VPS; приватная папка `cooks`, путь `{user_id}/{uuid}.jpg`. nginx отдаёт их только по подписанным сервером ссылкам на 1 час (модуль `secure_link`); автор и друзья получают такие ссылки в ответах API. Размер загрузки ограничен 500 КБ для фото и 2 МБ для карточки.
- **«Обогнал друга»:** после записи `cooks` сравниваем число стран пользователя до и после с числом стран друзей; возвращаем имя одного друга, которого пользователь обогнал.
- **Неделя в рейтинге** — с понедельника 00:00 по часовому поясу пользователя, который запрашивает рейтинг.
- **События оплаты** (`payment_success`) пишет сервер в вебхуке, а не клиент.
- **Ошибки** — единый формат `{error: {code, message}}`; коды (`unauthorized`, `paywall`, `rate_limited`, `not_found`, `validation`) описаны в `packages/shared`.

## Интеграция с Telegram

Telegram даёт нам вход без регистрации, приглашения через ссылки, оплату в Stars и уведомления через бота. Точные названия методов и версии Bot API агент сверяет с актуальной документацией Telegram перед реализацией.

**Авторизация**

- Клиент передаёт сырую строку initData в каждом запросе.
- Сервер проверяет подпись по алгоритму Telegram: секрет = HMAC-SHA256 токена бота с ключом `WebAppData`, затем HMAC-SHA256 отсортированных полей и сравнение с `hash`. Данные старше 24 часов отклоняются.
- Токен бота хранится только на сервере, в переменных окружения (`.env` на VPS, не в git).

**Запуск и приглашения**

- Мини-апп открывается через кнопку меню бота, кнопку в сообщении `/start` и прямую ссылку `t.me/<бот>/<приложение>?startapp=<код>`.
- `startapp` содержит код приглашения пользователя (`users.invite_code`). При любом входе по такой ссылке сервер создаёт дружбу в обе стороны, если её ещё нет и код не принадлежит самому пользователю. `invited_by` записывается только для новых пользователей; событие `invite_joined` — тоже только для новых.

**Оплата в Stars**

- Сервер создаёт ссылку на счёт методом `createInvoiceLink`: валюта `XTR`, пустой `provider_token`, одна позиция с ценой тарифа. Для месячного тарифа используется подписка с периодом 30 дней (`subscription_period`), годовой — разовый платёж на 365 дней.
- Клиент открывает счёт через `openInvoice` и обрабатывает статус: `paid`, `cancelled`, `failed`.
- Вебхук бота отвечает на `pre_checkout_query` (проверка, что тариф и пользователь корректны) и на `successful_payment` записывает подписку. Обработка идемпотентна по `telegram_payment_charge_id`.
- Продление месячной подписки приходит новым `successful_payment` с `is_recurring`; сервер создаёт новую запись, `starts_at` = окончание предыдущего периода, `expires_at` берётся из `subscription_expiration_date`. Любая покупка при действующей подписке (например, годовой тариф при активном месячном) начинается после окончания текущего периода.
- Для возвратов сохраняем `telegram_payment_charge_id`; возврат делается методом `refundStarPayment` вручную администратором, после чего запись получает статус `refunded` и перестаёт давать доступ.
- Для приёма платежей у бота должны быть команды `/terms` и `/paysupport` (требование Telegram).

**Бот**

- `/start` — приветствие и кнопка «Открыть»; с параметром — то же, плюс приглашение.
- Напоминание об ужине: одно сообщение в день в `reminder_time` по часовому поясу пользователя, только при `reminder_enabled` и `bot_can_write`. В сообщении — блюдо дня (первая карточка выдачи «Будни») и кнопка открытия мини-аппа. Управляется в профиле.
- `bot_can_write` становится true, когда пользователь нажал `/start`, разрешил запись в `requestWriteAccess` или пришёл с `allows_write_to_pm` в initData. Если отправка вернула 403 (бот заблокирован), флаг сбрасывается.
- Напоминания по умолчанию включены у тех, кто нажал `/start`; у остальных — выключены до разрешения в профиле.
- Рассылка — по расписанию (процесс-воркер на Node), с соблюдением лимитов Bot API на частоту отправки.

**Интерфейс внутри Telegram**

- При запуске: `ready()`, `expand()`; учёт безопасных отступов (`safeAreaInset`, `contentSafeAreaInset`).
- Системная кнопка «Назад» на вложенных экранах.
- Тактильная отдача (`HapticFeedback`) на штампе и завершении шага.
- В режиме готовки отключаются вертикальные свайпы закрытия.
- Шаринг штампа: история через `shareToStory` (картинка + ссылка-приглашение) и сообщение в чат через подготовленное inline-сообщение (`savePreparedInlineMessage` + `shareMessage`). Если метод не поддерживается клиентом — запасной вариант через `openTelegramLink` на `t.me/share/url`.
- Картинки карточек лежат в публичной папке `share` по пути `{uuid}.jpg` (неугадываемое имя), nginx отдаёт их без подписи; `shareToStory` требует публичный URL. Личные фото из папки `cooks` туда попадают только в составе карточки, которой пользователь сам решил поделиться. Картинки старше 30 дней удаляет воркер.
- Тема в MVP — светлая, фиксированная; цвета Telegram не подхватываем. Чтобы шапка и фон Telegram не остались тёмными, при запуске вызываются `setHeaderColor` и `setBackgroundColor` с цветами из токенов.

## Стек и архитектура

Фронтенд — статическое React-приложение внутри Telegram; бэкенд и бот — Node.js-сервер с Postgres. Всё работает на одном VPS за nginx на своём домене, который стабильно открывается из России; облачных бэкенд-сервисов нет.

**Компоненты**

1. **Мини-апп** — статическая сборка, открывается внутри Telegram.
2. **nginx** — на VPS, единая точка входа на своём домене: TLS, раздача статики мини-аппа, реверс-прокси `/api/*` на Node-сервер, раздача файлов `/media/share/*` (публично) и `/media/cooks/*` (только по подписанной ссылке, `secure_link`).
3. **Node-сервер** — HTTP API для клиента (включая вход по initData) и вебхук бота `/api/bot/webhook`.
4. **Воркер** — отдельный Node-процесс из того же кода: напоминания по расписанию и очистка старых картинок `share`.
5. **Postgres** — на том же VPS, доступен только серверу и воркеру. **Файлы** — на диске VPS: приватная папка `cooks` и публичная `share`.
6. **Telegram** — Bot API (счета, сообщения, prepared messages) и клиент Telegram с SDK мини-аппа.

Клиент никогда не пишет в базу напрямую: каждое действие проходит через функцию, которая проверяет пользователя и права доступа.

**Стек**

| Часть | Технологии |
| --- | --- |
| Мини-апп | React 19, TypeScript (strict), Vite, `@tma.js/sdk-react` (преемник `@telegram-apps/sdk-react`), React Router, Redux Toolkit (состояние) и RTK Query (запросы и кеш), zod, Tailwind CSS с токенами из макета |
| Сервер | Node.js 24, TypeScript (strict), Fastify, Postgres 17, Drizzle ORM и SQL-миграции, файлы на диске |
| Бот | grammY в Node-сервере, режим вебхука |
| Инфраструктура | VPS, nginx (TLS, статика, реверс-прокси, `secure_link`), Docker Compose (Postgres, сервер, воркер, nginx) |
| Общий код | `packages/shared`: zod-схемы API, типы, константы (лимиты, цены, уровни) |
| Тесты | Vitest + Testing Library, MSW для моков API, Playwright для сквозных сценариев в dev-режиме |
| Инструменты | npm workspaces, ESLint, Prettier, TypeScript project references |

**Структура репозитория**

```
apps/web/            мини-апп
  src/app/           роутинг, провайдеры
  src/screens/       по папке на экран
  src/components/    общие компоненты UI
  src/store/         Redux store, слайсы
  src/api/           RTK Query: API-слайс и эндпоинты
  src/telegram/      обёртки SDK, mock-окружение
  src/mocks/         MSW-обработчики и фикстуры
apps/server/         Node-сервер
  src/routes/        эндпоинты API
  src/bot/           бот (grammY)
  src/worker/        напоминания, очистка share
  src/db/            схема Drizzle, запросы
  migrations/        SQL-миграции
  seed/              скрипт загрузки контента
packages/shared/     схемы и типы
deploy/              nginx.conf, docker-compose для VPS

AGENTS.md            правила для агентов
```

**Режим разработки без Telegram**

Агенты и разработчик должны запускать и проверять приложение в обычном браузере.

- `VITE_TG_MOCK=1` — подставное окружение Telegram (SDK умеет `mockTelegramEnv`): тестовый пользователь, тема, безопасные отступы. Набор тестовых пользователей переключается параметром `?user=`.
- `VITE_API=mock` — все запросы обслуживает MSW по фикстурам: 12 стран на 3 континентах, 36 блюд, 3 друга; состояния «новичок», «8 стран», «10 стран без подписки», «10 стран с подпиской», «бот не может писать». Двенадцать стран нужны, чтобы у состояния «10 стран» оставались закрытые страны.
- `VITE_API=local` — локальный Node-сервер и Postgres в Docker с seed-данными; initData подписывается тестовым токеном бота.
- Команда `npm run check` = типы + линтер + юнит-тесты; `npm run e2e` = Playwright по основным сценариям в mock-режиме.

**Хостинг:** всё на одном VPS за nginx на своём домене, который стабильно открывается из России (провайдер VPS — в открытых вопросах). База и файлы копируются в резервное хранилище вне VPS раз в сутки. Перед закрытым тестом доступность проверяется с российских мобильных операторов и домашних провайдеров.

## Нефункциональные требования

**Производительность**

- Первый экран интерактивен за 2 секунды на 4G и телефоне среднего класса.
- Стартовый JS-бандл — не больше 200 КБ в gzip; экраны, кроме главного, грузятся лениво. Размер проверяется в `npm run check` (size-limit); для схем на клиенте используется `zod/mini`.
- Фото блюд из контента — WebP, до 1200 px по длинной стороне, ленивая загрузка.
- Фото пользователя сжимается на клиенте до 1600 px по длинной стороне, JPEG 80%, не больше 500 КБ.
- Рецепт, открытый в режиме готовки, кешируется: при обрыве связи шаги продолжают показываться.

**Безопасность и данные**

- Сервер не доверяет клиенту: штампы, доступ к странам и подписка определяются только на сервере.
- Обработка платежей идемпотентна; повторный вебхук не создаёт вторую подписку.
- Храним минимум данных Telegram: id, имя, username, фото профиля.
- Фото блюд видят только автор и его друзья — кроме карточек, которыми автор сам поделился (папка `share`).
- Секреты (токен бота, пароль базы, ключ подписи ссылок) — только в серверном окружении, не в клиентской сборке.

**Доступность и удобство**

- Контраст текста — не меньше 4.5:1; зоны нажатия — не меньше 44 × 44 px.
- В режиме готовки шрифт шага — не меньше 20 px.
- Кнопки и поля — настоящие элементы `button`, `input`, `label`; у иконок без подписи — `aria-label`.

**Совместимость**

- Telegram для iOS и Android последних двух мажорных версий; Telegram Desktop — базовая работоспособность.
- Методы SDK, которых нет в старой версии клиента, проверяются средствами SDK (`isAvailable` / `ifAvailable` / `supports` — сверяют версию Mini Apps клиента) и имеют запасной вариант.

**Язык**

- Только русский. Все строки интерфейса — в одном файле `src/i18n/ru.ts`, чтобы позже добавить другие языки.

## Принятые решения

- Фото для штампа необязательно; экран настойчиво предлагает его сделать.
- Бесплатные 10 стран — любые на выбор пользователя.
- Пейвол показывается при открытии блюда закрытой страны; рецепт закрыт до оплаты.
- Бесплатный пользователь с 10 странами видит на главном экране 2 доступных блюда и 1 блюдо с замком.
- Бэкенд — свой Node.js-сервер с Postgres на VPS за nginx; Supabase и другие облачные бэкенды не используются. Клиент ходит только на свой домен.
- Время напоминания по умолчанию — 18:00; в онбординге не спрашиваем, меняется в профиле.
- Свинина — это мясо: отдельного варианта и тега нет. Кроме мяса, острого и глютена пользователь может указать свои исключения — они работают как поиск по названию блюда и ингредиентам.
- «Семья с детьми» не исключает острое автоматически.
- Онбординг светлый, как всё приложение.
