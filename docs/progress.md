## Заметки

Проблемы и идеи, замеченные вне текущей задачи. Пункт удаляется, когда его взяли в работу.

- e2e: если в окружении заданы `HTTPS_PROXY`/`all_proxy` (так было в песочнице агента 2026-10-16), проверка готовности dev-сервера Playwright (`webServer.url`) уходит в прокси, получает 503 и падает по таймауту 60 с; помогает `NO_PROXY=localhost,127.0.0.1,::1 npm run e2e`. Можно прописать `NO_PROXY` в `webServer.env`/скрипте `e2e` или проверять готовность по `port`.
- e2e: под высокой нагрузкой машины (load average > 15) сценарии изредка падали по таймауту `page.goto` на холодном dev-сервере; на свободной машине стабильно зелёные. Если повторится в CI — поднять `timeout`/`navigationTimeout` в `playwright.config.ts`.
- `.env.example`: добавить `MEDIA_URL=/media` (базовый URL фото контента, решение 0018), `MEDIA_SIGNING_KEY=` с комментарием «секрет подписи ссылок на фото, ≥ 32 символов [A-Za-z0-9_-], `openssl rand -hex 32`» и закомментированный `# MEDIA_DIR=/abs/path` (по умолчанию `apps/server/media`) — решение 0019; агенту правка `.env*` закрыта хуком.
- Осиротевшие фото готовок (загружены, но `POST /cooks` не последовал) не удаляются; по решению пользователя (2026-10-17) пока оставляем. Если понадобится — удалять в воркере (задача 21) файлы `cooks/` старше суток, на которые нет ссылки в `cooks.photo_path`.
- Лимит загрузок фото готовок (40 за 24 ч, решение 0019) считается по mtime файлов в папке пользователя `cooks/{user_id}/`; если в задаче 21 появится чистка осиротевших фото, удалённые файлы перестанут учитываться — лимит тогда считать иначе (например, по таблице или журналу загрузок).
- `.env.example` (задача 18, решение 0020): добавить серверные переменные бота: `WEBAPP_URL=` (https-адрес мини-аппа для кнопок бота; без него вебхук бота выключен), `PUBLIC_URL=` (https-origin сервера, только для `npm run bot:setup`), `# TERMS_URL=`, `# PRIVACY_URL=` (страницы документов для `/terms`), `# SUPPORT_CONTACT=` (@username или почта для `/paysupport`); без последних трёх бот отвечает заглушками. Контакт поддержки по оплате пока не выбран.
- Задача 19 (решение 0021): после мёржа запустить `npm run bot:setup` повторно — в `allowed_updates` добавлен `pre_checkout_query`; затем проверить оплату в тестовой среде Telegram: приходит ли `pre_checkout_query` при автопродлении (отказ «Подписка уже оформлена» действует, только пока до конца месяца больше 3 дней — если продление приходит раньше, расширить окно) и какой `telegram_payment_charge_id` принимает `editUserStarSubscription` у продлений. Новых переменных окружения нет.
- Bot API (июль 2026) добавил апдейт `subscription` (`BotSubscriptionUpdated`: canceled / active / failed) — не обрабатывается (решение 0021); пригодится, если понадобится показывать «продление отключено» или реагировать на неудачное списание.
- `.env.example` (задача 20, решение 0022): добавить `MINI_APP_LINK=` с комментарием «прямая ссылка мини-аппа `https://t.me/<бот>/<приложение>` для кнопки-приглашения в сообщении со штампом; без неё (или без `WEBAPP_URL`) штамп отправляется ссылкой через `t.me/share/url`»; значение должно совпадать с `VITE_BOT_USERNAME` / `VITE_APP_SHORT_NAME`.
- Задача 20 (решение 0022): на реальном Telegram не проверены `shareToStory` (iOS/Android) и `savePreparedInlineMessage` + `shareMessage` (Telegram скачивает `photo_url` карточки — нужен публичный https). Фото контента пока нет, поэтому карточка без снимка пользователя рисуется с плиткой вместо фото блюда.
- Модель данных ТЗ (таблица `users`, `cooks`) не отражает колонки, добавленные задачами: `users.bot_started_at` (решение 0020), `cooks.share_card` (решение 0022), `users.reminder_sent_on` (решение 0023). ТЗ не правили — дополнить таблицу при следующем обновлении ТЗ.
